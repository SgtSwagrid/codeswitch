## Project overview

This is a Scala browser plugin that teaches you a language by translating a few words of every page you read.

- It is written with [Omnibrowser](https://github.com/SgtSwagrid/omnibrowser): one object extending `BrowserExtension` defines the plugin, and the `sbt-omnibrowser` plugin (added by the synced `project/plugins-browser-plugin.sbt`) compiles it to JavaScript with Scala.js and lays it out for Chrome and Firefox.
- Its languages are [Megalingual](https://github.com/SgtSwagrid/megalingual)'s `Language`, with their names in every language, flags, tag matching and codec, and its language menus are Megalingual's `LanguagePicker` (`megalingual-laminar`), released dependencies from Maven Central like Iris. A change Code Switch needs in them is made and released in Megalingual. Code Switch adds only `spaced`, `whole` and `alike` (`Languages.scala`) and `Learner.own`; it never matches on every language.
- It asks a large language model through [Iris](https://github.com/SgtSwagrid/iris), a released dependency from Maven Central (`build.sbt`). A change Code Switch needs in Iris is made in Iris's own repository and released there (its `CLAUDE.md`, *Releases*); then a PR here moves `build.sbt` to that version. Scala Steward proposes new Iris releases here too.
- It puts its translations and hints into pages, and shows their tooltips, through [Annotated Text Format](https://github.com/SgtSwagrid/annotated-text-format)'s `annotated-text-format-dom` (`Passage`, `Decorator`, `Hovering`, `Tooltip`), and finds the hints' passages by its `annotated-text-format-llm` anchoring (`QuotedAnnotation.anchor`): released dependencies from Maven Central like Iris, of one version (`annotatedTextFormat` in `build.sbt`). A change Code Switch needs in them is made and released in Annotated Text Format (to try one first, `publishLocal` it there as a snapshot, its `CLAUDE.md` says how, from a clean checkout of its `main`, not a working copy with another session's changes). Its `TextSpan` is Code Switch's too.
- `sbt omnibrowserBuild` builds it unpacked, for development, under `target/**/omnibrowser/development/<browser>/`, which a browser can load as it is.
  `sbt omnibrowserPackage` zips it for release, under `target/**/omnibrowser/release/`, its bundles minified by esbuild (since Omnibrowser 0.7.0, through `npx`): the main bundle is about 2.22 MB (554 KB gzipped), and the content bundle 1.47 MB (380 KB gzipped). It fails if a file is too large for Firefox Add-ons to parse (5 MiB), which rejected 0.2.0, whose main bundle was 6.49 MB unminified.
- Files in `src/main/extension`, such as icons, are copied into the plugin as they are.
- Versions come from git tags (`v1.2.3` is `1.2.3`), by sbt-dynver. Publishing a GitHub release packages it and attaches the zips (`publish.yml`).
- `docs/PRIVACY_POLICY.md` is general on purpose, so that it need not follow internal changes: it says only what kinds of data go to which kinds of service, and what stays in the browser. Never add how the plugin works (what is sent with what, how much text, which provider or dictionary by name). Change it, and its date, only when that changes, as when data goes to a new kind of service.

### Architecture

- `Codeswitch` wires the parts, as methods (`background()`, `contentScripts()`, `popup()`): the storage keys (`native`, `fluent`, `learning`, `foreign`, `intensity`, `scope`, `blocked` and `allowed` in sync storage; `apiKeys`, keyed by `LlmProvider.key`, in local), the tab's `problem` (a `Shared.tab`, which each page's content script owns, so it lasts as long as the page and its badge), the `translate`, `hints` and `render` messages, the `dismiss` and `address` tab messages, the background that answers them (through `reporting`), the content script and the popup. Only `model` (sync) is on `Translator`, beside the default and codec it is built from.
- Omnibrowser 0.6.0 took circe's codecs, under which a derived enum is stored as `{"Case": {}}`. So `Language` (by its code, Megalingual's codec), `LlmModel` (by `name`) and `Level` (by name) have codecs of their own, which keep each as a plain string; keep them so. The `CodeswitchSuite` and `TranslatorSuite` tests pin the stored forms.
- The reader's languages are in three lists, and every other language is foreign: their own, `native`; the others they read fluently, `fluent` (none by default); and those they are learning, `learning` (none by default), each a `Learnt` with the reader's CEFR `level` in it. `Learner` holds `fluent`, a `NonEmptyList` with the native first (`Learner.native`), and `learning`; `Learner.chosen` makes it from the stored three, each one of the `learnable` languages (`learnable.resolve`), each once (by its `whole` language, the first kept), without a fluent one alike the native. `learnable` is a Megalingual `Localised` of every language but Chinese and German (Switzerland): a broader one (German) is learnt and explained in as itself, by its English name, but Chinese, in no script, would leave the script to the model, which could mix them across a page's batches, so it reads as its first variety, Simplified Chinese, whether chosen, stored or preferred by a browser (`zh`); likewise German (Switzerland), `de-CH`, what Swiss browsers send, is both Swiss Standard German and the dialects, so it reads as Swiss Standard German (`de-CH-1996`). Traditional Chinese (`zh-Hant`), a script, is learnt as itself. The pickers offer `learnable.listed` (`Popup.offered`), every language, those two among them, and nest each variety beneath its own, as Megalingual's picker does; the popup stores a choice as the language it reads as, so choosing Chinese keeps `zh-CN`. A language is the same as another (`alike`) if both are varieties of one `whole` language: the broadest of its lineage under its own primary tag, so German of Swiss Standard German, but Swiss German (`gsw`) itself, though Megalingual has it beneath German (Switzerland). So Swiss German is a language of its own: a German reader may learn it, and it may be learnt beside German, with its own dictionary (Kaikki's Alemannic German), ratings and cache. The browser's detector knows no Swiss German, so a page in it is found as German unless its `lang` says `gsw` and the text is too short to tell. A passage in a fluent language, or in none known, has a share of its words shown in the languages being learnt (`Learner.switches`), each word in one drawn for it (`Learner.into`, each as likely, so that one request holds them all); a passage in a learnt language, in any variety (`Learner.learnt`, which wins over fluency), has its words above the reader's level in it marked, explained in `native`; a passage in any other language, a foreign one, is translated whole into `native` (`Learner.translates`, below), unless the reader chose to leave them (`foreign`: `Foreign.Translate`, the default, or `Leave`, stored by name). A passage in no language known is switched, not translated whole. Nothing is marked while nothing is learnt and foreign passages are left (`Learner.active`), and there are no other switches: each kind of marking is on while its lists have languages. `native` is stored as `None` until the reader chooses it, and is then taken as the first language the browser prefers that is not being learnt, else English (`Learner.own`, from Megalingual's `Browser.preferences`), so that a browser in a learnt language, in any variety (`alike`), does not make it the reader's own; the content script follows the learner (any of its four keys, merged with `parJoinUnbounded`, which costs about 1 KB as `switchMap` already brings parJoin in), deduplicated, and `None` while it is not active. Any change restores the page and starts a new pass, as glosses and hints depend on all of it.
- Which websites have anything marked (`scope`, sync, a `Scope` kept by its name): every one but those `blocked` (`Except`, the default), or only those `allowed` (`Only`), each list its own (`Codeswitch.listOf`), both `[]` by default, so that switching keeps each; `Scope.leaves` says whether a page its list covers, or not, is left alone. The lists hold `Site`s (`Site.scala`, pure, tested in Node through its global `URL`), each a domain (lower case, punycode, without a dot at its end), any port but `80` and `443`, the path's segments and the query, all as the browser's `URL` parses and percent-encodes them, each code in upper case, so a typed `Über` or `%c3%9c` matches `location.href`'s `%C3%9C`. `Site.parse` takes an address typed or pasted, with or without `http(s)://` (or `https:/`, a typo; `schemed`), dropping a leading `*.`, the fragment, credentials and a slash at the end; anything else (`chrome://`, `file://`, text with spaces, which Chrome's `URL` takes as a host with `%20`s, or the host `https` of `https//example.com`; `named`) is none. `www.` is kept, never stripped, as `www.gov.uk` would widen to `gov.uk`, and "Add this site" on `www.google.com` would cover Gmail. `covers`: the same domain or one under it (`sub.example.com`, not `notexample.com`), or the domain without the site's `www.` (`www.example.com` covers `example.com`, not `news.example.com`), the same port if the site gives one, a segment prefix of the path (`/docs` covers `/docs/guide`, not `/docsy`; paths are case-sensitive), and every parameter of its query among the page's (`youtube.com/watch?v=abc` covers `?t=42&v=abc`). It is stored as its `address` (encoded), shown as its `text` (its domain's labels in their own script, by `Punycode`, RFC 3492's decoding, and the rest `decodeURI`d where it may be), and the lists are `lenient`. The content script (only the top frame's, as Omnibrowser sets no `all_frames`, so `window.location.href` is the address bar's) first waits while the page is left alone (`ignoring(...).find(!_)`), so such a page gets no tooltips, listeners, shared problem or anything else; once started, `readers` gives `None` while it is left alone, so blocking an open page restores it, as a learner change does, keeping the pass numbers going (a fresh `Reader.read` would number its passes from 0 again, colliding with the marks left on the page's nodes). Both re-read on a change of `scope`, either list, or the address, polled each second (`moves`), as a single-page app moves without loading (`whenever`: read at once, then after each trigger, deduplicated): `popstate` misses `pushState`, the isolated world cannot wrap the page's `history`, and `tabs.onUpdated` gives no URL without host access; the poll reads only `location.href`, and storage only when it changes. The content script serves `address` (`location.href`) for its life, even while it waits, so the popup can offer to allow a page left alone. As `moves` and `Highlighter.nodes` tick apart, a single-page app's move into a blocked path could send the new view's text before `readers` hears of it, so each request (`translate`, `hints`, `render`, `define`) first checks the address as it is then (`unlessIgnored`), giving none unasked if the page is left alone: nothing of such a page leaves the browser.
- Each passage's language is found once per pass (`Reader.detect`, 16 passages at once): Omnibrowser's `languages.detect` on the passage's own text, or, where that is not reliable (short text, and always in Safari, which has no detector), the `lang` of the nearest element (`Highlighter.declared`); a tag the browser finds reliably but Megalingual does not know falls back to the `lang` too (`foundLanguage`). The words of each passage found are counted by language for the pass (`Tally`, in `Highlighter.learn`), and once a batch is found, each passage found in none takes the language of most of them (`Highlighter.prevail`), as headings, captions and the like, too short to tell, are in the page's; with no language found at all, a passage counts as in none known, so its words are switched, as a fluent one's are. It is kept on the passage's element (`codeswitchLanguage`, a `Known` of the pass). `choose` takes words only from passages looked at in the pass that the learner `switches` (`switchesFound`), so that one the page put in while the others were being looked at waits for the next tick, rather than being switched as of no language, and perhaps hinted after; and `unread` gives only those in a learnt language that `reads`, each excerpt with its `Learnt`, each passage marked read for the pass (`codeswitchRead`).
- Reading (`Reader.read`): each passage's own text (`Highlighter.own`, a `Passage` in which passages within it are one placeholder, as they are read apart) is cut between sentences (`Words.excerpts`, which segments the text once, and cuts a longer sentence between its words) into excerpts of at most about 100 words (`Reader.nearExcerpts`), so that the hints for one fit in a reply. Each keeps a live DOM `Range` (`Passage.rangeOf`), which follows it as hints placed in the excerpts before it split its texts, and its hints are placed only within it (`Passage.spanOf`). Excerpts go in `hints` requests nearest first (below), each batch split by its learnt language (`Reader.apart`), so that a request (`Passages`: the `Learnt` and the texts) is of one language, and its prompt names the language and the reader's level in it. Each hint carries its language (`Hint.language`), by which it is rated and looked up. The reply is a list of each passage's entries (`Translator.Marked`, read by Iris, below); one with more or fewer passages is `Problem.unmatchedHints`. The content script turns any failure to find hints into none (`hinting`), keeping why as the page's problem, so that a failed request never stops the pass, which a failed translation does. `Learnt.reads` is false at C2, above which there is nothing, and in Chinese, Japanese and Thai (`spaced`), whose words `Words.occurrences` cannot find, so nothing is sent for them, though words are still switched into them; the popup's note under such a language says why. The model gives entries of the word or phrase, its meaning in `native` (which may give several translations, shown on hovering), its gloss (the one of them that reads in its place, in the form it needs, as models gave lists that broke the sentence when shown inline), whether it is a cognate or loanword the reader would understand as readily as the word of `native` like it (never a false friend), its CEFR level and its dictionary form (below); `Translator.hints` drops cognates, which the level alone marked however transparent (`geomorphologisch`), and keeps the rest above the reader's level, as `Learnt.kind` bands them: one level up is `Explained` (kept, teal), further up `Glossed` (replaced by the gloss, or the meaning if it is blank, `codeswitch-gloss`, grey). `Words.place` (pure) quotes each as Annotated Text Format does (a phrase in parts joined by ` … `) and anchors them with `QuotedAnnotation.anchor`: in order, from where the one before begins, as written before in any case or spacing (a hint for `Weg` goes on `Weg` before `weg`), as whole words (not part of a word joined by a hyphen or apostrophe, either apostrophe for either), or else wherever its words occur only once, so a hint given out of order may still be placed; it leaves out what it cannot find, a point, or what overlaps one before. Each is one annotation, its `Marking` saying how it is shown: a phrase in parts (`ruft … an`) is explained in each part, never glossed, and lit together on hovering (`codeswitch-hint-lit`, outlined by `content.css`, as are a translation's pieces, `codeswitch-lit`). A gloss is capitalised only where it begins a sentence (`Words.opens`). `Highlighter.hint` decorates the excerpt's hints at once (`decorate`, under the prefix `codeswitch-hint`, each hint whole or not at all), in a `Try`, so a page that changed under it loses only those hints. Hints hold no draw, so the intensity never hides them.
- Translating whole (`Reader.render`): each passage in a foreign language, not yet read in the pass, is cut into its parts, the text of each of its own text nodes (`Highlighter.foreign`, through `Passage.offsetOf`, as the library's own list of them is private, each at a live `Range`), so that a link's or emphasis's text keeps its element. Into a spaced native language a part leaves the spacing at its ends in the page; into one not spaced it takes it in, so that no space is left between its words. A part longer than `Reader.characters` (2400) is cut between sentences, or else every so many characters (`Words.pieces`), and a passage into stretches of at most that, as a language without spaces counts few words: passages go in `render` requests nearest first, weighed by characters, about 600 in sight, else 2400, a list of each passage's parts in, and out a `Rendition` of each (its `parts`, as many and in order, described in its Scaladoc alone); a passage given back in more or fewer parts is left as it is, and more or fewer passages is `Problem.unmatchedPassages`. As for hints, a failure translates none and keeps why as the page's problem (`Codeswitch.rendering`). `Highlighter.render` puts each part's translation in place of its part, as the page is now (`Passage.spanOf`), as one decoration of the passage (`codeswitch-rendered`, each part whole or not at all, not highlighted but faintly underlined by `renderLook`'s `beneath`), but only parts that still hold what was read (`unchanged`, as `wordOf` checks a word: one text, not left, not rewritten), leaving one given back unchanged as it is, and one given back empty as nothing, but for one within a link, button or label, which keeps its original, as `sparing` keeps their text. Where the page has no space between two parts, as a language without spaces has none, a spaced native language's translation is spaced off the one before, but not before closing punctuation nor after opening (`Words.spacedAfter`). Hovering any part shows the whole passage's original (`Rendered.original`) in a tooltip of its own (`Tips.renderings`, labelled "Original", which the pointer passes through, so its text is cut after a dozen lines rather than scrolled, `Tips.originals`), but for parts within links, buttons and the like, decorated apart and covered by no tooltip, as a tap on one would first show the original rather than follow the link. The intensity does not touch them; restoring and pruning take them out as they do translations and hints.
- The word list (`Familiarity`): over a hint or a translation, the card has a button for each `Answer`, on a scale of five (`point`, 1 to 5, between "Didn't know" and "Knew it", each named "1, Didn't know" and so on): 1 to 3 move the word's familiarity down towards 0, by all, two thirds and a third of `step` (0.15) of the way, 4 ("Mostly knew it") leaves it be, and 5 moves it `step` of the way up towards 1 (`Answer.pull`, `Familiarity.after`), so 0.5 goes to 0.425, 0.45, 0.475, 0.5 or 0.575. The first real press each time the tooltip opens (`answered`; `isTrusted`, so a page's `.click()` does nothing) counts.
  - `FamiliarityService` (in `Familiarity.scala`) is the one source of every word's familiarity, Alec's rule: a rating and a default are alike to all that reads them. A word's familiarity is its rating (`familiarity:<code>:<word>`, `Familiarity.key`, by the code of the word's `whole` language, `de` for `de-DE` and `gsw` for Swiss German, so that every variety shares a rating, in the model's case, so `Weg` and `weg`, or Italian and Spanish `burro`, stay apart), or else `Familiarity.default`: from its CEFR level, its difficulty, against the reader's level in its language (`learntIn`, by `alike`), as a hint of it is shown, a level above 0.5, further 0.2, at or below `known` (0.8), and 0.5 where either level is unknown, as for a translation, which has none. `Hint.level` keeps the model's level (`Translator.hintOf`), and `Headword.level` and `Rating.level` carry it, `None` for a translation (`Translated.headword`). Any part reads (`of`, for the content script's hints, `all`, for the popup, `total`), but only the background writes, as it answers the `rate` and `seen` messages (`Codeswitch.rated`, `sighted`, which, like `define`, refuse a language not being learnt), one write at a time under `FamiliarityService.lock`, so that the sum of every word's familiarity, `familiarityTotal` (`Familiarity.total`, a `Total` of the `sum` and the `learning` it was counted for, for normalising), kept with each write (`share`: a word rated or seen counts its familiarity, else nothing), is never lost to another tab's write. A change of level moves every default without a write, so a `Total` of other levels is counted afresh from every word (`tallied`) before the next write applies. Frequency (`FrequencyService`) and priority (`PriorityService`) are another session's, built on it.
  - Every word the reader sees shown is kept as seen, rated or not: `Highlighter.hint`, `show` and `reveal` give the `Headword`s they put in sight (placed and not hidden, `shown`), and `Reader` hands them to `Asking.seen`, which sends `seen`; a translation shown only once the intensity rises is seen then. `seen:<code>:<word>` holds a `Sighting` (the level, if ever known, and the part of speech and meaning where it was last seen, `Familiarity.sighting`), written only when it changes. The model gives the dictionary form in each entry (`word`; `Hint.word`; the word itself if blank), and of each translation (`Translation.word`, below). When hints are shown, the content script reads the familiarity of every hinted word (`Asking.familiarity`, `FamiliarityService.of`), which decides its kind (`Familiarity.apply`): from 0.8 it is `Known`, kept with a faint underline (`codeswitch-known`: a transparent highlight, and a 1 px half-opaque teal underline drawn beneath it by the look's `beneath`) and still rateable, above 0.35 explained, else glossed; a word not rated keeps the kind its level gave it. Only words the model gives above the reader's level are marked, so a rated word that it puts at or below their level is not. Both tooltips are interactive (the library's: it stops the pointer's and keys' events at its host, and keeps a press from taking the page's focus), and stays open while the pointer crosses from the word's line to it, above or below the word. Its buttons are a labelled group with `aria-pressed`, a row made for each opening, so the first press in the row counts (`Cards.answered`). Each excerpt's hints are one stop of Tab (`Focus.Roving`), the left and right arrow keys moving among them, each showing its tooltip, Tab moving on to its buttons and Enter pressing one; Known words, and hints within links, take no focus, so a long article is not hundreds of stops. Translations take none at all (`Focus.Off`): they are on most pages the reader browses, and the library gives hidden annotations the focus too, so a translation that the intensity hides would be a stop showing nothing; their buttons are reached by the pointer or a tap alone. A tap of a touch or pen shows it too; on a word in a link, a second tap follows the link. A page's own capture listeners on `window` or `document` still see the tooltip's clicks before it stops them, so a page's click-outside handler may still fire.
- The dictionary, for the card in each tooltip (`Cards`, below): the `define` message takes a `Lookup` (a word's dictionary form, part of speech, meaning and language: a hint's, or the original that a translation stands for and the language it was translated into, `Word.into`, kept on its `Translated`, the meaning cut to `Lookup.longest`; `Lookup.checked` trims it, drops a part of speech not in `Lookup.parts`, and refuses an empty or over-long one, as a page's content script may send anything) and gives a `Card`: an `Entry`, in Wiktionary's shape (senses with glosses and examples, forms tagged as Wiktionary tags them, IPA, etymology, `Source`), with its principal forms and tables laid out by the background (`Card.of`, so `Forms` stays out of the pages' bundle) and the Wiktionary page it is from (`Wiktionary.page`, `en.wiktionary.org/wiki/<word>#<Kaikki's name>`), which the card credits (CC BY-SA). The background looks the word up in its `language`, explained in the reader's `native` (`Dictionary.entry`, `Translator.explained` and `defined` take the native, not a `Learner`), and a card's word is rated in its language (`Headword.language`). The hints' and translations' parts of speech are checked against `Lookup.parts` too. Words from pages, and Wiktionary's text, go only in a request's user message, never its system prompt.
  - Kaikki: `Wiktionary.url` is `kaikki.org/dictionary/<name>/meaning/<1st letter>/<1st two>/<word>.jsonl`, of the word composed (NFC) with `.` as `_dot_` and `/` as `_slash_`, the folders taken from that (`z. B.` is at `z/z_/z_dot_ B_dot_.jsonl`), each part percent-encoded. Kaikki has dictionaries of whole languages, so `<name>` is the `whole` language's English name, as Megalingual gives it, but Norwegian (`nb`) is "Norwegian Bokmål", Croatian and Serbian "Serbo-Croatian", Filipino "Tagalog", Slovenian "Slovene" and Swiss German "Alemannic German" (`Wiktionary.nameOf`); a test checks every whole language against Kaikki's index (`src/test/resources/kaikki/languages.txt`). Paths are case-sensitive. Kaikki sends no CORS headers, so the background needs a host permission for it, `Wiktionary.host` in `hosts`, required. It asks nothing more of a reader who updates: the content scripts' `http://*/*` and `https://*/*` already give Chrome's one warning, "Read and change all your data on all websites", with or without it (checked with `chrome.management.getPermissionWarningsByManifest` from the worker, which needs no permission). `Dictionary.read`: a 404 is no entry, any other failure (offline, 429, 5xx) fails the lookup and keeps nothing.
  - An entry's `genders` are those of `Entry.genders` (masculine, feminine, neuter, common, in that order) that every glossed sense is tagged with (`Wiktionary.agreed`), as Kaikki tags each sense with its heading's gender (`Bank f`, `дом m inan`); several (Spanish `mar`) if each sense has several, none if the senses disagree, and none for a verb. Animacy (`inanimate`, Polish `animal-not-person`) is not kept. `Translator.explained` is not sent them, and keeps them (`explainedAs` copies the entry).
  - Of a word's entries (one per etymology, as `Bank` the bench and `Bank` the bank), `Wiktionary.candidates` keeps those with senses, of its part of speech if any are, at most four, and `choose` takes the one whose best gloss most fits the meaning, by the share of the gloss's words in it. The glosses are English, so for a reader of another language all the candidates are first put into theirs in one request (`Translator.explained`: glosses, translations and etymology; the reply must have as many entries, senses and examples, and the examples' text is kept as Wiktionary's), then chosen among. If that cannot be done (no key, a model error, an unreadable reply), they are given in English and not kept. A kept translation is used only if it still `fits` the entry in its place (word, part of speech, number of senses), as Kaikki may reorder a word's entries. Where Kaikki has nothing, a model writes the entry (`Translator.defined`, tagging each form only with the tags that `Forms` lays forms out by, `Forms.tags`, so a Finnish noun gets all its cases; single-word forms only, at most 60; and a noun's genders, `Defined.genders`, kept only if of `Entry.genders`), whose forms all count as of a table (`source = Some("model")`); one with no senses is none, and kept, but a reply that cannot be read fails the lookup like any model error. The model's client is asked for only then (`Dictionary.Ask`), so a word Wiktionary has needs no key for an English reader.
  - The cache, local, word last in each name so no word can pass for another: Kaikki's entries for a word, `wiktionary:<learnt>:<word>` (none kept for a 404); each candidate put into the reader's language, `explained:<learnt>:<own>:<index>:<word>`; a model's entry, `made:<learnt>:<own>:<pos>:<word>`, `<learnt>` the code of the lookup's `whole` language (`de` for `de-DE`) and `<own>` the reader's variety's (`en-GB`), as they explain in it. A reader of any English (`alike`) gets Wiktionary's English as it is (kept even if none, as asking again costs as much). Only the `Dictionary.capacity` (300) latest used are kept, their names in `dictionary`, latest first, changed under a `Semaphore` (`Semaphore.in[SyncIO, IO]`, as the background has no resource to hold one; a test with slow storage fails without it); the list is written before the value, so that nothing is kept unlisted, and a write that fails, as when storage is full, is ignored. Each part of a lookup (fetching, translating, making) asked for again while in flight is waited for, not repeated (`Once`, by the part's cache name, so lookups of a word in different senses share one fetch); it is `uncancelable` between registering and starting, `poll`ing the program, lest a cancelled first leave the others waiting for ever. A model request that failed is not made again for `Dictionary.pause` (a minute; `unlessFailed`, `noting`), its failure given meanwhile; only requests made are noted, inside `Ask`'s `use`, so a missing key is not, and a key just given is used at once. `forgetFailures` clears them between tests. Entries keep only the forms a card shows (`Forms.kept`).
  - `Forms` (pure) lays forms out, the same way in every language, as Wiktionary tags them alike. Only the forms of a source's first table count (`Wiktionary.firstTables`: each table begins with a `table-tags` form), which leaves out Spanish forms with clitics and the reflexive, German subordinate-clause and compound tenses, and Russian spellings from before 1918; then none tagged `combined-form`, `multiword-construction`, possessive or `object-*`, nor dashes or pronunciations (French tables give IPA). One `onInput` handler on the popup's root clears the problem, as each control's input event bubbles up to it, except the slider's, which clears it on `change`. The slider is named by `aria-labelledby` and read out by `aria-valuetext`, its `<output>` hidden from screen readers. All run their programs through `browser.run`, never `unsafeRunAndForget`.
- Laminar stays out of the pages' bundle too, within `popup()` and `Popup`: `grep -c com.raquo` on `omnibrowser-content.js` should find nothing. The content script edits the host page's text nodes directly, in plain DOM, through the library.
- `hosts` grants the background each provider's API (from Iris's `LlmProvider.origin`), so its requests do not depend on the API allowing CORS.
- Codecs are derived (`derives Codec`, circe's), except those of what is stored as a plain string: `Language` (its code, by Megalingual's codec), `LlmModel` (its `name`) and `Level` (its name). `Foreign` and `Scope` are kept by their names too. A derived one would store an object, as a `Learnt` is stored (`{"language": "de", "level": "B1"}`). The lists `fluent` and `learning` leave out an item that cannot be read, as of a code no language has (`Codeswitch.lenient`), rather than reading as their default; their codecs are named givens, as Omnibrowser's `StorageKey` takes an `Encoder` and a `Decoder` apart, so that an explicit `(using codec)` fills only one, and anonymous givens of two `Codec[List[_]]`s clash. Stored values from earlier releases need not stay readable, and the keys that only they kept (`language`, `level`, `translating`, `reading`) are taken out on install, update and start (`Codeswitch.retire`).

### Gotchas

- A `/*` in a comment, as in a match pattern like `https://*/*`, opens a nested comment in Scala.
- On Windows, if `sbt` cannot start its server, run it with `sbt --server`.
- To build against a local snapshot of Omnibrowser (its `publishLocal`), set `omnibrowserVersion` to it in an uncommitted `.sbt` file, and take the plugin's own `omnibrowser-core` out (`libraryDependencies ~= (_.filterNot(m => m.name == "omnibrowser-core" && m.revision == "0.7.1"))`, at the plugin's version): the plugin adds core at its own version, and `update` refuses the snapshot over it as a possibly incompatible eviction, which neither `dependencyOverrides` nor `libraryDependencySchemes` excuses.
- `Browser.Storage.all` (Omnibrowser after 0.7.1) is abstract, so the tests' in-memory `Memory` storage implements it too.
- Run `omnibrowserPackage` in an sbt of its own, not after `testFull` or `omnibrowserBuild` in one invocation: so run, its release link of the content bundle once hung for 15 minutes (`OmnibrowserPlugin.linkContent` awaiting it, no CPU), where alone it takes 20 s. A hung sbt left behind holds the build's boot lock ("server is already booting"), so no other sbt starts there until it is stopped.
- On Windows, a script that rewrites a source file in text mode (as Python's `open(p, 'w')`) writes CRLF. Scalafmt mends the code but not multi-line string literals, such as the model's instructions, which then hold `\r`; write with `newline=''`, and check with `git diff`'s CRLF warning.
- On Windows, if compiling fails with "A required privilege is not held by the client" while backing up a `.sjsir`, delete `target/out/sjs1/**/classes` (sbt 2's disk cache links them) and compile again.
- Git here pushes a branch to its upstream (`push.default=tracking`), and the token may bypass the ruleset that guards `main`. A branch made from `origin/main` tracks `main`, so `git push origin <branch>` lands on `main` without a PR. Make branches with `--no-track`, and push with an explicit target: `git push -u origin HEAD:refs/heads/<branch>`.

## Instructions

### Compilation and Diagnostics

- When the user asks for help with a compilation or type error, start by running `sbt compile` to see the error for yourself.
  If there are many errors, making it unclear which one the user is referring to, ask them to clarify, and then focus only on that issue.
- IntelliJ MCP integration is active. When a request seems to implicitly refer to something the user is looking at, always check
  `mcp__ide__getDiagnostics` first to see which file(s) are open and get associated diagnostics (errors, warnings, and info hints with line numbers).

#### Testing

- After making code changes, always run `sbt compile` to verify that issues are fixed and no new ones are introduced.
- Repeatedly retry upon failure until the build succeeds. If you are unsure how to fix an issue, ask for help or refer to existing code for examples.
- Before trying to fix an error, make sure you first understand it fully.
- You should never report that a feature is complete without testing it first.

### Code Style

- You must read the [Code Style Guidelines](docs/STYLE_GUIDE.md).

### Pull Requests

When asked to publish the code changes, your task is to open one or more pull requests (PRs) to merge the changes into `main` on GitHub:

- Use `git` to check what has changed as compared to the `main` branch on `origin`.
- If the changes are thematically linked, they can be published as a single PR.
- Otherwise, you'll need to divide the changes into multiple PRs using your own judgement.
- Each PR should have a singular focus, shouldn't break anything, and should be able to be merged independently.
- Ensure that all code is staged, committed and pushed. Ensure no new files are left uncommitted, and no debug code is left in the codebase.
- When creating a PR, ensure that the title and description are clear, informative, and comprehensive.
- All feature/bugfix/etc branch names should be formatted as "feature_<short description>" or "fix_<short description>" or similar.
- All PR titles should be formatted as "[<scope>] <Short summary>", e.g. "[renderer] Fixed colour inversion bug."
- Use the `gh` CLI to do the above.

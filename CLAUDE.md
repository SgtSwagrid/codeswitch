## Project overview

This is a Scala browser plugin that teaches you a language by translating a few words of every page you read.

- It is written with [Omnibrowser](https://github.com/SgtSwagrid/omnibrowser): one object extending `BrowserExtension` defines the plugin, and the `sbt-omnibrowser` plugin (added by the synced `project/plugins-browser-plugin.sbt`) compiles it to JavaScript with Scala.js and lays it out for Chrome and Firefox.
- Its languages are [Megalingual](https://github.com/SgtSwagrid/megalingual)'s `Language`, with their names in every language, flags, tag matching and codec, and its two language menus are Megalingual's `LanguagePicker` (`megalingual-laminar`), released dependencies from Maven Central like Iris. A change Code Switch needs in them is made and released in Megalingual. Code Switch adds only `spaced` and `alike` (`Languages.scala`) and `Learner.own`; it never matches on every language.
- It asks a large language model through [Iris](https://github.com/SgtSwagrid/iris), a released dependency from Maven Central (`build.sbt`). A change Code Switch needs in Iris is made in Iris's own repository and released there (its `CLAUDE.md`, *Releases*); then a PR here moves `build.sbt` to that version. Scala Steward proposes new Iris releases here too.
- `sbt omnibrowserBuild` builds it unpacked, for development, under `target/**/omnibrowser/development/<browser>/`, which a browser can load as it is.
  `sbt omnibrowserPackage` zips it for release, under `target/**/omnibrowser/release/`.
- Files in `src/main/extension`, such as icons, are copied into the plugin as they are.
- Versions come from git tags (`v1.2.3` is `1.2.3`), by sbt-dynver. Publishing a GitHub release packages it and attaches the zips (`publish.yml`).

### Architecture

- `Codeswitch` wires the parts, as methods (`background()`, `contentScripts()`, `popup()`): the storage keys (`language`, `translating`, `intensity`, `reading`, `native` and `level` in sync storage; `apiKeys`, keyed by `LlmProvider.key`, in local), the tab's `problem` (a `Shared.tab`, which each page's content script owns, so it lasts as long as the page and its badge), the `translate` and `hints` messages, the `dismiss` tab message, the background that answers them (`asking`, then `reporting`), the content script and the popup. Only `model` (sync) is on `Translator`, beside the default and codec it is built from.
- Omnibrowser 0.6.0 took circe's codecs, under which a derived enum is stored as `{"Case": {}}`. So `Language` (by its code, Megalingual's codec), `LlmModel` (by `name`) and `Level` (by name) have codecs of their own, which keep each as a plain string; keep them so. The `CodeswitchSuite` and `TranslatorSuite` tests pin the stored forms.
- There are two modes, each switched on its own: `translating`, of pages in other languages (below), and `reading`, of passages in the language being learnt. `Learner` holds the language, `native`, `level` and both switches. `native` is stored as `None` until the reader chooses it, and is then taken as the first language the browser prefers that is not being learnt, else English (`Learner.own`, from Megalingual's `Browser.preferences`), so that a browser in the learnt language, in any variety (`alike`), does not make it the reader's own; the content script follows it (any of its five keys, merged with `parJoinUnbounded`, which costs about 1 KB as `switchMap` already brings parJoin in), deduplicated, and `None` while no language is chosen or both are off. Any change restores the page and starts a new pass, as glosses and hints depend on all of it.
- Each passage's language is found once per pass (`Reader.detect`, 16 passages at once): Omnibrowser's `languages.detect` on the passage's own text, or, where that is not reliable (short text, and always in Safari, which has no detector), the `lang` of the nearest element (`Highlighter.declared`); with neither, the passage counts as in another language, as before. It is kept on the passage's element (`codeswitchLanguage`, a `Known` of the pass). `choose` skips passages in the language being learnt, and `unread` gives only those, each marked read for the pass (`codeswitchRead`).
- Reading (`Reader.read`): each passage's own text (`Passage(block, own = true)`, where passages within it are one placeholder, as they are read apart) is cut between sentences (`Words.excerpts`, which segments the text once, and cuts a longer sentence between its words) into excerpts of at most about 300 words, so that the hints for one fit in a reply. Each keeps a live DOM `Range` (`Passage.rangeOf`), which follows it as hints placed in the excerpts before it split its texts, and its hints are placed only within it (`regionOf`). Excerpts go in `hints` requests of about 300 words. The reply is a list of each passage's entries (`Translator.Marked`, read by Iris, below); one with more or fewer passages is `Problem.unmatchedHints`. The content script turns any failure to find hints into none (`hinting`), keeping why as the page's problem, so that a failed request never stops the pass, which a failed translation does. `Learner.reads` is false at C2, above which there is nothing, and in Chinese, Japanese and Thai (`spaced`), whose words `Words.occurrences` cannot find, so nothing is sent then; the popup's note says why. The model gives entries of the word or phrase, its meaning in `native`, its CEFR level and its dictionary form (below); `Translator.hints` keeps those above the reader's level, as `Learner.kind` bands them: one level up is `Explained` (kept, teal, its meaning in `data-codeswitch-tip`), further up `Glossed` (replaced by the meaning, `codeswitch-gloss`, grey). `Words.place` (pure) finds each in order as whole words, any spacing, in its own case where it can (`seek`: a hint for `Weg` goes on `Weg` before `weg`), after the first part of the one before, leaving out what it cannot find or that overlaps; a phrase in parts (`ruft … an`) is explained in each part, never glossed. A gloss is capitalised only where it begins a sentence (`Words.opens`). `Highlighter.hint` makes each part an `Edit` like a translation's, from the end back, all in a `Try`, so a page that changed under it loses only those hints. Hints hold no draw, so the intensity never hides them.
- The word list (`Familiarity`): over a hint, the tooltip has a button for each `Answer` (Knew it 1.0, Unsure 0.6, Didn't know 0.0). The first real press each time the tooltip opens (`answered`; `isTrusted`, so a page's `.click()` does nothing) moves the word's familiarity `step` (0.15) of the way to its mark, from where its hint's kind puts an unrated word (explained 0.5, glossed 0.2), as kept in `data-codeswitch-kind`, so a split phrase starts from its own level, not from its being explained. Each word has a local key of its own, `familiarity:<code>:<word>` (`Familiarity.key`, by the root language's code, `de` for `de-DE`, so that every variety shares a rating, and a language stored as a whole one is rated and read under one key), in the model's case, so `Weg` and `weg`, or Italian and Spanish `burro`, stay apart, and a rating never rewrites another's; two tabs rating the same word at the same moment could still lose one. The model gives the dictionary form in each entry (`word`; `Hint.word`, `data-codeswitch-word`; the word itself if blank). When hints are shown, the content script reads the familiarity of each hinted word (`Codeswitch.familiarities`), and a rated word's decides its kind in place of its level (`Familiarity.apply`): from 0.8 it is `Known`, kept with a faint underline (`codeswitch-known`) and still rateable, above 0.35 explained, else glossed. Only words the model gives above the reader's level are marked, so a rated word that it puts at or below their level is not. Nothing else is tracked. A hint's tooltip takes pointer events (`codeswitch-rating`), stops pointer and mouse events there (and the default of `mousedown`, so the page keeps its focus), and stays open while the pointer is within the union of the word's line box and its own (`Tooltip.bridges`), which may be above or below the word. Its buttons are a labelled group with `aria-pressed`; keyboard and touch cannot reach them yet, which belongs with the annotation library's tooltip host. A page's own capture listeners on `window` or `document` still see the tooltip's clicks before it stops them, so a page's click-outside handler may still fire.
- The dictionary (for the card on hovering a hint, whose display waits for the annotation library's tooltip host): the `define` message takes a `Lookup` (a hint's dictionary form, part of speech and meaning; `Lookup.checked` trims it, drops a part of speech not in `Lookup.parts`, and refuses an empty or over-long one, as a page's content script may send anything) and gives an `Entry`, in Wiktionary's shape (senses with glosses and examples, forms tagged as Wiktionary tags them, IPA, etymology, `Source`). The hints' part of speech is checked against `Lookup.parts` too. Words from pages, and Wiktionary's text, go only in a request's user message, never its system prompt.
  - Kaikki: `Wiktionary.url` is `kaikki.org/dictionary/<name>/meaning/<1st letter>/<1st two>/<word>.jsonl`, of the word composed (NFC) with `.` as `_dot_` and `/` as `_slash_`, the folders taken from that (`z. B.` is at `z/z_/z_dot_ B_dot_.jsonl`), each part percent-encoded. Kaikki has dictionaries of whole languages, so `<name>` is the root's (`lineage.last`) English name, as Megalingual gives it, but Norwegian (`nb`) is "Norwegian Bokmål", Croatian and Serbian "Serbo-Croatian", Filipino "Tagalog" and Slovenian "Slovene" (`Wiktionary.nameOf`); a test checks every root against Kaikki's index (`src/test/resources/kaikki/languages.txt`). Paths are case-sensitive. Kaikki sends no CORS headers, so the background needs a host permission for it, which ships with the card (required or optional is the user's call then); for now `hosts` has none, so add `https://kaikki.org/*` locally to check it live. `Dictionary.read`: a 404 is no entry, any other failure (offline, 429, 5xx) fails the lookup and keeps nothing.
  - Of a word's entries (one per etymology, as `Bank` the bench and `Bank` the bank), `Wiktionary.candidates` keeps those with senses, of its part of speech if any are, at most four, and `choose` takes the one whose best gloss most fits the meaning, by the share of the gloss's words in it. The glosses are English, so for a reader of another language all the candidates are first put into theirs in one request (`Translator.explained`: glosses, translations and etymology; the reply must have as many entries, senses and examples, and the examples' text is kept as Wiktionary's), then chosen among. If that cannot be done (no key, a model error, an unreadable reply), they are given in English and not kept. A kept translation is used only if it still `fits` the entry in its place (word, part of speech, number of senses), as Kaikki may reorder a word's entries. Where Kaikki has nothing, a model writes the entry (`Translator.defined`, with Wiktionary's tags, single-word forms only, at most 60), whose forms all count as of a table (`source = Some("model")`); one with no senses is none, and kept, but a reply that cannot be read fails the lookup like any model error. The model's client is asked for only then (`Dictionary.Ask`), so a word Wiktionary has needs no key for an English reader.
  - The cache, local, word last in each name so no word can pass for another: Kaikki's entries for a word, `wiktionary:<learnt>:<word>` (none kept for a 404); each candidate put into the reader's language, `explained:<learnt>:<own>:<index>:<word>`; a model's entry, `made:<learnt>:<own>:<pos>:<word>`, `<learnt>` the root's code (`de` for `de-DE`) and `<own>` the reader's variety's (`en-GB`), as they explain in it. A reader of any English (`alike`) gets Wiktionary's English as it is (kept even if none, as asking again costs as much). Only the `Dictionary.capacity` (300) latest used are kept, their names in `dictionary`, latest first, changed under a `Semaphore` (`Semaphore.in[SyncIO, IO]`, as the background has no resource to hold one; a test with slow storage fails without it); the list is written before the value, so that nothing is kept unlisted, and a write that fails, as when storage is full, is ignored. Each part of a lookup (fetching, translating, making) asked for again while in flight is waited for, not repeated (`Once`, by the part's cache name, so lookups of a word in different senses share one fetch); it is `uncancelable` between registering and starting, `poll`ing the program, lest a cancelled first leave the others waiting for ever. A model request that failed is not made again for `Dictionary.pause` (a minute; `unlessFailed`, `noting`), its failure given meanwhile; only requests made are noted, inside `Ask`'s `use`, so a missing key is not, and a key just given is used at once. `forgetFailures` clears them between tests. Entries keep only the forms a card shows (`Forms.kept`).
  - `Forms` (pure) lays forms out, the same way in every language, as Wiktionary tags them alike. Only the forms of a source's first table count (`Wiktionary.firstTables`: each table begins with a `table-tags` form), which leaves out Spanish forms with clitics and the reflexive, German subordinate-clause and compound tenses, and Russian spellings from before 1918; then none tagged `combined-form`, `multiword-construction`, possessive or `object-*`, nor dashes or pronunciations (French tables give IPA). A verb's rows are person, or else gender (a Russian past), and number; its columns are the known tense and mood tags (a tense without a mood is indicative; `negative` makes its own column), named in a fixed order, a tense left out of the name where no other column has its mood. If any column has a single-word form, columns of only several words (compound tenses with an auxiliary, as Finnish has for each) are left out; a separable verb's are all of several words, so German `rufe an` is kept. Participles, infinitives and gerunds are principal forms, not rows. Tables are laid out only for the languages and parts of speech checked against real files (`Forms.checked`: verbs of German, Spanish, Italian, Portuguese, French, Finnish and Russian; nouns of German, Finnish, Russian, Turkish and Polish), by the root, so a variety counts; others (Dutch, with no person in the plural; Swedish and Danish, with none at all; Polish verbs, with genders beside persons; Hungarian's definite conjugation; Turkish verbs) have their principal forms alone, and only those are kept. Add a language only with a fixture and tests of its tables. A noun's rows are every case it has (Finnish has 14), against number, without forms of several words (as with an article) unless all are. The tests read real Kaikki files in `src/test/resources/kaikki` (through `Kaikki`, with Node's `fs`, each file's language from its `lang_code`), of German, Spanish, Italian, Portuguese, French, Finnish, Russian, Turkish, Polish and Dutch words.
  - Checked against live Kaikki in Chrome by sending `{omnibrowser: "define", request}` with `chrome.runtime.sendMessage` from the popup page.
- Pages load their own bundle, `omnibrowser-content.js`, holding only what `contentScripts()` and `Codeswitch`'s own values reach; the main `omnibrowser.js` is for the background and popup. So `Codeswitch`'s values must not reach Iris or `Translator` (`model`'s codec and default reach Iris's model lists, and `hosts` is a `def` for `LlmProvider`): put what only the background or popup needs in their methods or on `Translator`. The release content bundle is about 3.39 MB (499 KB gzipped); Megalingual's `Language` and its tag matching added 82 KB (5.5 KB gzipped) over Code Switch's own, measured against main's 3.31 MB. Nothing of Laminar, nor Megalingual's names or flags (which only `name`, `title` and `flag` reach), may reach it: `grep -oE 'com\.raquo\.[a-z]*|megalingual\.names'` on it should find nothing. With the `define` message's codecs, which pages will need for the card, it is about 3.44 MB. Before, it was about 3.25 MB (the word list adds 20 KB): circe's codecs (Omnibrowser 0.6.0) took it from 2.82 MB to 3.12 MB, and the reading mode adds 114 KB (13 KB gzipped). It was 3.89 MB when pages loaded the main bundle; `grep -o 'com\.alecdorrington\.iris\.[A-Za-z]*'` on it should find nothing.
- The content script (`Reader`) watches the learner and, for each in turn (`switchMap`), restores the page, then marks its body and every node added to it, a pass at a time. `Highlighter` does all DOM work: it chooses words in text nodes (marking each node with the pass and the intensity its words were drawn up to, which each text that `split` takes off it copies, so that its words are not drawn again), and shows each word's translation as its model laid it out (below), each piece a `span.codeswitch` holding the original in `data-codeswitch`, styled by `src/main/extension/content.css` (put in every page by the manifest, through `withCss`).
- A translation (`Translation`, in `Placement.scala`) is a list of `Piece`s, each with a `Place`: the word's own (`Home`), a run of up to `Placement.reach` words around it (`Replacing`, as an article with its noun), or beside a quoted anchor (`After`/`Before`, as a German verb at the end of its clause); several pieces split a word (a separable verb), and none declines it. `Placement.lay` (pure, tested in Node) finds the places in the passage's text: a run within the word's own text node, of at most `reach` words split at spaces and with no digits; an anchor's nearest occurrence within the word's sentence, as a whole word (`Words.occurrences`: not part of a word joined by a hyphen or apostrophe, either apostrophe for either). Any piece without a place declines the whole translation, and so does one that would empty a link, button or label (`Highlighter.empties`).
- If no piece stays in the word's place, its place becomes an empty `span.codeswitch-gap`, and so does the space beside it (perhaps in the next text node, as for a word alone in `<em>`; never a line break, which `pre-wrap` keeps), so that no two spaces are left together. A moved piece is a `span.codeswitch-inserted` holding the space and its `span.codeswitch`. `restore()` removes the inserted spans, then puts each gap's and translation's `data-codeswitch` back, which must give the page's text exactly.
- `Choice` keeps its word as a live DOM `Range`, which follows the word as other translations split its text node, and is checked against the word before showing. A live range that begins where an element is inserted keeps beginning at the end of the text before it, so the element falls within it: `wordOf` first moves such a start to the next text with prose (`settle`).
- `show` takes each batch's choices from the last back, each in a `Try`. It lays each translation out in its `Passage` as it is then (`Highlighter.shown`): the passage's prose texts, each element within `skipped` that shows anything (ours included) as one U+FFFC, so that a space beside one of our spans is not taken as beside the word, but a gap as the text it shows (nothing, or its original while hidden) and a hidden piece as nothing. A gap counted as U+FFFC kept the next word that moved from taking the space beyond it: "what I have seen." with both moved, the earlier shown first (as words from separate batches or rescans may be), read "evah nees what I .". It finds each edit's text and offsets before making any, and makes them from the end of the passage back, a replacement before an insertion at the same place. The pieces put in one place go in as one `DocumentFragment`, as separate insertions at a node's start would come out reversed.
- Edits split a text node only within it, never at its ends; a replacement at a node's start leaves the page's node itself, empty, after the element, as a page or framework may hold on to it. Each text split off, each element put in a text's place, and the text that restore puts back for it are marked with the page's text they came from (`codeswitchOrigin`), and `restore()` joins each run of them that is still side by side back into it, so the page keeps its own text nodes, whole, even if a page script has since put something between them.
- The intensity (0 to 40%, 5% by default, from the popup's slider) is the share of words translated. Each word is drawn a number from 0 to 1 and is translated while the intensity is above it, so changing it never redraws the page:
  - A rise draws each text's remaining words again from its mark's level up (`Words.choose`'s `floor`), keeping those shown. `Reader` keeps the intensity in a cats-effect `Ref`, and `Highlighter.nodes` rescans the body on the next one-second tick after a rise, but only once the page is shown (`outOfSight`), so that the tabs in the background don't all ask at once. fs2's `merge`, `concurrently` and `hold1Resource` added 68 KB to the pages' bundle, so keep them out of it; so too Scala's `toDoubleOption`, so draws are read with `parseFloat`.
  - A fall hides the translations above it at once, asking for nothing; a rise back shows them again. `show` gives each part of a translation its draw in `data-codeswitch-draw`, and creates it hidden if the intensity is below that. A hidden part takes the class `codeswitch-hidden`: a `.codeswitch` or gap shows its `data-codeswitch`, keeping what it showed in `data-codeswitch-translation`, and an inserted piece is emptied, its parts kept on it (`stow`), so that the page's `textContent` is its original text. `restore()` still gives that back.
  - A change of intensity never restores the page; a change of the learner does (above).
- Known limits, from the review of #21: `empties` reads `textContent`, so a link whose other text is screen-reader-only or a lone arrow can still be emptied to the eye, and it covers only some roles; `<br>` and block children join with no separator, in placement and in the context; `Passage` is rebuilt for each placement, and for each text with a word chosen; a run joined by non-breaking spaces counts as one word; code and `.notranslate` text are left out of contexts ("Run `npm install` now" is sent as "Run now"); a framework that writes into the emptied page node gets its text doubled on restore, as before; a word whose space beside it is in a hidden translation's gap is declined, as that space is not in a text node; and the DOM paths (`Edit` order, `settle`, `join`) are covered only by the end-to-end check.
- `Tooltip` shows the original of the translation or gloss under the pointer, or the meaning of an explained word (`Highlighter.tipOf`), above it (below it in the window's top line, and kept within its sides), as a manual popover appended to `<html>`, in the top layer. It was a CSS `::after` on the span, which the page hid for about one word in fifteen: off the top of the window, clipped by `overflow` boxes (sidebars, nav bars, tables) or covered by sticky headers in another stacking context. Keep it out of the page's layout. `all: initial !important` in its rule would show it while closed, so `:not(:popover-open)` hides it.
- A word's context is the text around it within its passage (the nearest `p`, `li`, cell, heading, `div`, ...), so that a word in a link or `<em>` still has its sentence; never only its own text node, which for such a word is the word alone. `Passage.around` gives it as the page said it: our translations and gaps as their originals, and elements within `skipped` (code, scripts, text fields, `.notranslate`) as a space, so their text is not sent. `Words.context` collapses spacing and keeps 100 characters on each side, or more to reach the ends of the word's sentence, up to 300; `…` marks where either side is cut, and the model is told to decline a word whose translation belongs past one. Sentences come from `Intl.Segmenter` (through a facade in `Words.scala`, using `containing`), or, where there is none (Firefox before 125), from their stops (`Words.byStops`).
- The background (`Codeswitch.translations`) reads the language and key, and asks Iris's `LlmClient` (`Translator`) for translations of a batch of words with their contexts, a JSON array of pairs in, and out a list for each word of its pieces (`Placed`: its `text`, with `replacing`, `after` or `before` where it is not shown in the word's place; none to decline). `[[ ]]` quoted in a place is dropped, and so is a piece in the word's place that only repeats the word (a model echoing the pairs it was given). A reply with more or fewer entries than words is `Problem.unmatched`, as which is which cannot be known: it fails the request like any problem, and the content script, which keeps it as the problem, then leaves every word as it is (`Codeswitch.recover`, which knows it by its message, as `Translator` stays out of the pages), as a failed request would end `Reader.pass` for good. The instructions also tell the model never to follow instructions in the contexts. A failure is badged `!` on the toolbar button of the tab that asked (`report`, from `serve`'s `Sender`), or of every tab if none did, and fails the request with the reason explained (`Translator.explain`), which the content script keeps as its tab's `problem` (`noting`, from `MessagingError.reason`) until a translation there succeeds. A success there clears its mark, and so does any change in the popup, for the tab it was opened over.
- Every request is Iris's `ask` of a type (`Placed`, `Marked`, `Explained`, `Defined`, private in `Translator`, each `derives Structured`): Iris tells the model its JSON Schema, described by the types' Scaladoc and `@param`s, so write those for the model; reads the reply back; and asks again, three times in all, for one it cannot read, then fails with `LlmError.Unreadable`, as it does at once for a reply cut off at the token limit or stopped by the provider. `explain` makes that `Problem.unreadable`, `cutOff` or `unanswered`, which, like `unmatched` (`Problem.ofBatch`), `recover` takes as a problem of the batch alone, leaving its words as they are and keeping the pass. So the system prompts give only the task, the languages and level, what the input is, and never to follow its instructions; what each field of an answer means, with its examples, is in the types' Scaladoc alone, never repeated in a prompt (Alec's rule), and nothing is parsed by hand. Scaladoc cannot interpolate, so `Placement.reach` (three words), `Lookup.parts` and the form tags are written out in it, and `TranslatorSuite`'s schema test pins them to the code and checks that the prompts leave the fields to the schema. The types that pages reach (`Level`, `Sense`, `Example`) never derive `Structured` themselves, which would bring Iris into the pages' bundle; `Translator` gives them `Structured.derived`, and `-Xread-docs` (`build.sbt`) has their Scaladoc (`@param`s, for their fields) read even when only `Translator.scala` is recompiled; but an edit to their Scaladoc alone reaches the schemas only once `Translator.scala` is recompiled, as a clean build does. A part of speech the model gives is kept only if it is one of `Lookup.parts` (`Lookup.part`), which both schemas name, as `Forms.kept` needs `verb` or `noun` exactly.
- The reader chooses any model Iris lists (`Translator.models`, by provider; Claude Haiku 4.5 by default), kept by `LlmModel.name` (`given Codec[LlmModel]` in `Translator`), and gives a key for its provider. The popup's key field shows the chosen model's provider's key, and keeps each provider's apart. Any change of settings in the popup clears the badge, and has the content script of the tab it was opened over forget its problem (`dismiss`, ignored where no content script runs).
- Code outside `Codeswitch` that uses `browser.storage` needs `(using Granted[Storage])`, as the grant is only given inside the extension object.
- The popup is rendered by Laminar (`LaminarPage`, from `omnibrowser-laminar`) and styled by `src/main/extension/popup.css` (`withStylesheets`). Each mode is a checkbox (`mode`) with a note, above its own settings (the intensity; the reader's language and level) in a `div.settings` that is `hidden` while it is off (not a `label`, which `popup.css` shows as a block, hidden or not). The two languages are Megalingual's `LanguagePicker`s (the learnt one `optional`, with "None"; the reader's own leading with each language's own name), each in a `field` rather than a `label`, which would pass a click on a choice to the picker's button; as they fire no input event, their observer also clears the problem (`chosen`). `popup.css` gives them the popup's colours through `--megalingual-*` properties. The other selects are `menu`s, but the models', which has groups. Stored settings come in as signals (`browser.signal(key)`), and the problem as the active tab's shared value (`browser.signal(Codeswitch.problem, tab)`, through `flatMapSwitch` on the active tab). The menus store their choices through `saver(key)`, as does the slider, on `change` (letting it go, or each key press), but not while a key held down repeats (`held`), when it stores only on `keyup`, as sync storage allows 120 writes a minute; never throttle it, as a timer's trailing write dies with the popup. It shows its value on `input`, which it stops from bubbling up, and ignores the stored value while it has focus, lest a step stored late move it back. The key field stores through `saving`, which wrap `browser.observer` so that the popup's foot shows its status: a spinner while any change is saving (for at least 500 ms, as a write is too quick to see, so typing keeps it spinning), then a tick and "Saved", which `popup.css` fades after 3 s, or "Not saved". `browser.run` runs a program synchronously up to its first asynchronous step (`syncStep`), and the popup may close at once, so `keep` calls `save` before anything asynchronous (starting a fiber, as `both` does, counts), timing the spinner with `IO.monotonic`. One `onInput` handler on the popup's root clears the problem, as each control's input event bubbles up to it, except the slider's, which clears it on `change`. The slider is named by `aria-labelledby` and read out by `aria-valuetext`, its `<output>` hidden from screen readers. All run their programs through `browser.run`, never `unsafeRunAndForget`.
- Laminar stays out of the pages' bundle too, within `popup()` and `Popup`: `grep -c com.raquo` on `omnibrowser-content.js` should find nothing. The content script edits the host page's text nodes directly, in plain DOM.
- `hosts` grants the background each provider's API (from Iris's `LlmProvider.origin`), so its requests do not depend on the API allowing CORS.
- Codecs are derived (`derives Codec`, circe's), except those of what is stored as a plain string: `Language` (its code, by Megalingual's codec), `LlmModel` (its `name`) and `Level` (its name). A derived one would store an object. Stored values from earlier releases need not stay readable.

### Testing

- The tests run in Node, which has no DOM: `Words`, `Placement`, `Translator`, `Tooltip.place` and the codecs are tested directly, and the background through `FakeBrowser` (whose pages are stand-ins without a DOM, so the content script and popup cannot be run there). `Translator` is tested against an sttp `BackendStub`.
- `Highlighter`, `Reader`, `Tooltip` and `Popup` were checked end to end in Chrome for Testing over CDP (Puppeteer's, in `~/.cache/puppeteer/chrome`, takes `--load-extension`), with Anthropic's API stood in for by `Fetch.fulfillRequest` in the service worker. Chrome's own component extensions also have a `background.js`; the plugin's worker is the one where `globalThis.__omnibrowser` is defined. As the content bundle is linked apart from the main one, check both the development and release builds. To check placement, have the stub answer each kind of piece in turn, save each passage's `textContent` from an inline script at the end of the test page, and compare after restoring (set `language` to `null`), with each passage's count of text nodes, which must not grow; count passages with two spaces together, and links left empty, too. Change settings under an open page with `chrome.storage.sync.set` in the worker: to check the intensity, group the parts of each translation by `data-codeswitch-draw`, and compare them and the requests after each change, and the page's `textContent` with the original at 0. To make the page seem hidden to the content script, override `document.visibilityState` in its isolated world (the `Runtime.executionContextCreated` context whose `auxData.type` is `isolated`; listen before `Runtime.enable`, which reports the contexts at once). In JavaScript sent inside a template literal, write `\\S` for a regular expression's `\S`.
- To hover, send `Input.dispatchMouseEvent` (`mouseMoved`), and after scrolling wait a frame first: `scroll` fires on the next frame, and hides the tooltip. `Page.captureScreenshot`'s `clip` is in page coordinates, not the viewport's.
- The reading mode was checked end to end in Chrome for Testing over CDP: a German page with no `lang` (so the browser's detector decides), an English page and a mixed one, with the stand-in answering by the system prompt (a hints request says "that are above their level") and recording what each request asked. Check that the German passages go only in `hints` requests and the English only in `translate`, each hint's text, tip and class, the tooltip on hovering each kind, a level change (re-read), each switch hiding its settings and restoring its pages, nothing asked with both off, and every page's text intact once `language` is `null`. A content script's `chrome.i18n` is not the page's, so check detection by its effect. For the word list, hover a hint, walk the pointer to its tooltip (which opens below a word near the top of the window), press its buttons with `mousePressed`/`mouseReleased`, read `familiarity` from the worker's `chrome.storage.local`, and reload: a word past 0.8 is no longer marked.
- sbt 2 caches passing suites, so `sbt test` may run only those whose code changed; `sbt testFull` runs them all (161).
- The shared problem was checked end to end in Chrome for Testing over CDP: with a language and no key, the page answers `chrome.tabs.sendMessage(tab, {omnibrowser: "omnibrowser/shared", request: "problem"}, {frameId: 0})` with the reason, and a `chrome.tabs.connect(tab, {name: "omnibrowser/shared/problem", frameId: 0})` port is sent `{value}` (or `{unshared: true}` where nothing shares it). The open popup follows its tab to the next page, even one whose content script runs late. With a key, and Anthropic's API answering more entries than words, the problem is `Problem.unmatched`'s message, each word stays as it is, and a paragraph added later is still asked for. Set `intensity` to `0.4` first, or a short test page may have no word drawn, and ask for nothing. To see console errors from a target's start, such as "Unchecked runtime.lastError", use `Target.setAutoAttach` with `waitForDebuggerOnStart`, enable `Runtime` and `Log` in each attached session, then `Runtime.runIfWaitingForDebugger`. The popup can be opened as a tab with `chrome.tabs.create({url: chrome.runtime.getURL("popup.html"), active: false})`, which leaves the page as the active tab it reads. `tabs.query` by URL needs host access, which the plugin lacks for pages, so find the page's tab another way.

### Gotchas

- A `/*` in a comment, as in a match pattern like `https://*/*`, opens a nested comment in Scala.
- On Windows, if `sbt` cannot start its server, run it with `sbt --server`.
- On Windows, a script that rewrites a source file in text mode (as Python's `open(p, 'w')`) writes CRLF. Scalafmt mends the code but not multi-line string literals, such as the model's instructions, which then hold `\r`; write with `newline=''`, and check with `git diff`'s CRLF warning.
- On Windows, if compiling fails with "A required privilege is not held by the client" while backing up a `.sjsir`, delete `target/out/sjs1/**/classes` (sbt 2's disk cache links them) and compile again.
- Git here pushes a branch to its upstream (`push.default=tracking`), and the token may bypass the ruleset that guards `main`. A branch made from `origin/main` tracks `main`, so `git push origin <branch>` lands on `main` without a PR. Make branches with `--no-track`, and push with an explicit target: `git push -u origin HEAD:refs/heads/<branch>`.

## Instructions

### Compilation and Diagnostics

- When the user asks for help with a compilation or type error, start by running `sbt compile` to see the error for yourself.
  If there are many errors, making it unclear which one the user is referring to, ask them to clarify, and then focus only on that issue.
- IntelliJ MCP integration is active. When a request seems to implicitly refer to something the user is looking at, always check
  `mcp__ide__getDiagnostics` first to see which file(s) are open and get associated diagnostics (errors, warnings, and info hints with line numbers).

#### Testing

- After making code changes, always run `sbt compile` to verify that issues are fixed and no new ones are introduced.
- Repeatedly retry upon failure until the build succeeds. If you are unsure how to fix an issue, ask for help or refer to existing code for examples.
- Before trying to fix an error, make sure you first understand it fully.
- You should never report that a feature is complete without testing it first.

### Code Style

- You must read the [Code Style Guidelines](docs/STYLE_GUIDE.md).

### Pull Requests

When asked to publish the code changes, your task is to open one or more pull requests (PRs) to merge the changes into `main` on GitHub:

- Use `git` to check what has changed as compared to the `main` branch on `origin`.
- If the changes are thematically linked, they can be published as a single PR.
- Otherwise, you'll need to divide the changes into multiple PRs using your own judgement.
- Each PR should have a singular focus, shouldn't break anything, and should be able to be merged independently.
- Ensure that all code is staged, committed and pushed. Ensure no new files are left uncommitted, and no debug code is left in the codebase.
- When creating a PR, ensure that the title and description are clear, informative, and comprehensive.
- All feature/bugfix/etc branch names should be formatted as "feature_<short description>" or "fix_<short description>" or similar.
- All PR titles should be formatted as "[<scope>] <Short summary>", e.g. "[renderer] Fixed colour inversion bug."
- Use the `gh` CLI to do the above.

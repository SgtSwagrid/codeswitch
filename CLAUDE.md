## Project overview

This is a Scala browser plugin that teaches you a language by translating a few words of every page you read.

- It is written with [Omnibrowser](https://github.com/SgtSwagrid/omnibrowser): one object extending `BrowserExtension` defines the plugin, and the `sbt-omnibrowser` plugin (added by the synced `project/plugins-browser-plugin.sbt`) compiles it to JavaScript with Scala.js and lays it out for Chrome and Firefox. The languages that text is written in (`browser.languages.detect`, `i18n.detectLanguage`, which only an extension may call) come from Omnibrowser's `omnibrowser-megalingual` module, as Megalingual's `Language`s (`build.sbt`, at `omnibrowserVersion`); the browser's voices (`Speech[IO]`) and the reader's preferred languages (`Browser.preferences`) come from Megalingual's own `megalingual-web`, as a web page has them too. A change Code Switch needs in either is made and released in its own library.
- Its languages are [Megalingual](https://github.com/SgtSwagrid/megalingual)'s `Language`, with their names in every language, flags, tag matching and codec, and its language menus are Megalingual's `LanguagePicker` (`megalingual-laminar`), released dependencies from Maven Central like Iris. A change Code Switch needs in them is made and released in Megalingual. Code Switch adds only `spaced`, `whole` and `alike` (`Languages.scala`) and `Learner.own`; it never matches on every language.
- It asks a large language model through [Iris](https://github.com/SgtSwagrid/iris), a released dependency from Maven Central (`build.sbt`). A change Code Switch needs in Iris is made in Iris's own repository and released there (its `CLAUDE.md`, *Releases*); then a PR here moves `build.sbt` to that version. Scala Steward proposes new Iris releases here too. Code Switch depends on `iris-providers`, as the reader chooses the provider at runtime (`Providers`). It prompts the chosen model's `PromptService` (Iris's prompt layer, made by `model.prompt` with `Translator.access` and `Translator.settings`, and wrapped in `SpendingService.charging`), and queries it for each answer (`prompt.query.send`). Iris (from 0.6) sends again a request the provider refused or failed for now, as `ApiConfig`'s defaults say (three more tries, within a minute), so a rate limit reaches the reader only once that is spent.
- It puts its translations and hints into pages, and shows their tooltips, through [Annotated Text Format](https://github.com/SgtSwagrid/annotated-text-format)'s `annotated-text-format-dom` (`Passage`, `Decorator`, `Hovering`, `Tooltip`), and finds the hints' passages by its `annotated-text-format-llm` anchoring (`QuotedAnnotation.anchor`): released dependencies from Maven Central like Iris, of one version (`annotatedTextFormat` in `build.sbt`). A change Code Switch needs in them is made and released in Annotated Text Format (to try one first, `publishLocal` it there as a snapshot, its `CLAUDE.md` says how, from a clean checkout of its `main`, not a working copy with another session's changes). Its `TextSpan` is Code Switch's too.
- `sbt omnibrowserBuild` builds it unpacked, for development, under `target/**/omnibrowser/development/<browser>/`, which a browser can load as it is.
  `sbt omnibrowserPackage` zips it for release, under `target/**/omnibrowser/release/`, its bundles minified by esbuild (since Omnibrowser 0.7.0, through `npx`): the main bundle is about 2.22 MB (554 KB gzipped), and the content bundle 1.47 MB (380 KB gzipped). It fails if a file is too large for Firefox Add-ons to parse (5 MiB), which rejected 0.2.0, whose main bundle was 6.49 MB unminified.
- Files in `src/main/extension`, such as icons, are copied into the plugin as they are.
- Versions come from git tags (`v1.2.3` is `1.2.3`), by sbt-dynver. Publishing a GitHub release packages it and attaches the zips (`publish.yml`).
- `docs/PRIVACY_POLICY.md` is general on purpose, so that it need not follow internal changes: it says only what kinds of data go to which kinds of service, and what stays in the browser. Never add how the plugin works (what is sent with what, how much text, which provider or dictionary by name). Change it, and its date, only when that changes, as when data goes to a new kind of service.

### Architecture

- The sources are in three packages beneath `com.alecdorrington.codeswitch`, each in a folder of its name in `src/main/scala`, its tests in the same in `src/test/scala`, with `Codeswitch` alone at the root:
  - `models`, the data and the pure logic over it (`Learner`, `Level`, `Hint`, `Placement`, `Words`, `Entry`, `Card`, `Forms`, `Wiktionary`'s reading of Kaikki, `Familiarity`, `Frequency`, `Priority`, `Site`, `Spending`), which uses nothing of the others;
  - `services`, what asks a model or a dictionary, or keeps what the reader knows, has met and has spent (`Translator`, `Lexicon`, `Revisions`, `FamiliarityService`, `FrequencyService`, `PriorityService`, `SpendingService`, `Arrivals`), each service in a file of its own, its models in `models`, which uses only the models;
  - `views`, what the reader sees, in pages, the popup and the editor (`Reader`, `Highlighter`, `Tips`, `Cards`, `Popup`, `Vocabulary`, `Recordings`, `Editor`), which uses the models, the services and `Codeswitch`'s keys and messages.
  - Each file imports by name what it uses of another package. A top-level definition that would be `private`, but that another package uses, is `private[codeswitch]`, as `Popup` is.
- `Codeswitch` wires the parts, as methods (`background()`, `contentScripts()`, `popup()`, `options()`, the lexicon's editor): the storage keys (`native`, `fluent`, `learning`, `foreign`, `intensity`, `scope`, `blocked` and `allowed` in sync storage; `apiKeys`, keyed by `Provider.id`, and `revised`, in local, beside the word list's, below), the tab's `problem` (a `Shared.tab`, which each page's content script owns, so it lasts as long as the page and its badge), the `translate`, `hints` and `render` messages, the `translated`, `hinted`, `dismiss` and `address` tab messages, the background that answers them (through `reporting`), the content script and the popup. Only `model` (sync) is on `Translator`, beside the default and codec it is built from, and `spent` (local) on `models.Spending`, beside how the popup shows it.
- Omnibrowser 0.6.0 took circe's codecs, under which a derived enum is stored as `{"Case": {}}`. So `Language` (by its code, Megalingual's codec), `Model` (by `name`) and `Level` (by name) have codecs of their own, which keep each as a plain string; keep them so. The `CodeswitchSuite` and `TranslatorSuite` tests pin the stored forms.
- The reader's languages are in three lists, and every other language is foreign: their own, `native`; the others they read fluently, `fluent` (none by default); and those they are learning, `learning` (none by default), each a `Learnt` with the reader's CEFR `level` in it. `Learner` holds `fluent`, a `NonEmptyList` with the native first (`Learner.native`), and `learning`; `Learner.chosen` makes it from the stored three, each one of the `learnable` languages (`learnable.resolve`), each once (by its `whole` language, the first kept), without a fluent one alike the native. `learnable` is a Megalingual `Localised` of every language but Chinese and German (Switzerland): a broader one (German) is learnt and explained in as itself, by its English name, but Chinese, in no script, would leave the script to the model, which could mix them across a page's batches, so it reads as its first variety, Simplified Chinese, whether chosen, stored or preferred by a browser (`zh`); likewise German (Switzerland), `de-CH`, what Swiss browsers send, is both Swiss Standard German and the dialects, so it reads as Swiss Standard German (`de-CH-1996`). Traditional Chinese (`zh-Hant`), a script, is learnt as itself. The pickers offer `learnable.listed` (`Popup.offered`), every language, those two among them, and nest each variety beneath its own, as Megalingual's picker does; the popup stores a choice as the language it reads as, so choosing Chinese keeps `zh-CN`. A language is the same as another (`alike`) if both are varieties of one `whole` language: the broadest of its lineage under its own primary tag, so German of Swiss Standard German, but Swiss German (`gsw`) itself, though Megalingual has it beneath German (Switzerland). So Swiss German is a language of its own: a German reader may learn it, and it may be learnt beside German, with its own dictionary (Kaikki's Alemannic German), ratings and cache. The browser's detector knows no Swiss German, so a page in it is found as German unless its `lang` says `gsw` and the text is too short to tell. A passage in a fluent language, or in none known, has a share of its words shown in the languages being learnt (`Learner.switches`), each word in one drawn for it (`Learner.into`, each as likely, so that one request holds them all); a passage in a learnt language, in any variety (`Learner.learnt`, which wins over fluency), has its words above the reader's level in it marked, explained in `native`; a passage in any other language, a foreign one, is translated whole into `native` (`Learner.translates`, below), unless the reader chose to leave them (`foreign`: `Foreign.Translate`, the default, or `Leave`, stored by name). A passage in no language known is switched, not translated whole. Nothing is marked while nothing is learnt and foreign passages are left (`Learner.active`), and there are no other switches: each kind of marking is on while its lists have languages. `native` is stored as `None` until the reader chooses it, and is then taken as the first language the browser prefers that is not being learnt, else English (`Learner.own`, from Megalingual's `Browser.preferences`), so that a browser in a learnt language, in any variety (`alike`), does not make it the reader's own; the content script follows the learner (any of its four keys, merged with `parJoinUnbounded`, which costs about 1 KB as `switchMap` already brings parJoin in), deduplicated, and `None` while it is not active. Any change restores the page and starts a new pass, as glosses and hints depend on all of it.
- Which websites have anything marked (`scope`, sync, a `Scope` kept by its name): every one but those `blocked` (`Except`, the default), or only those `allowed` (`Only`), each list its own (`Codeswitch.listOf`), both `[]` by default, so that switching keeps each; `Scope.leaves` says whether a page its list covers, or not, is left alone. The lists hold `Site`s (`Site.scala`, pure, tested in Node through its global `URL`), each a domain (lower case, punycode, without a dot at its end), any port but `80` and `443`, the path's segments and the query, all as the browser's `URL` parses and percent-encodes them, each code in upper case, so a typed `Über` or `%c3%9c` matches `location.href`'s `%C3%9C`. `Site.parse` takes an address typed or pasted, with or without `http(s)://` (or `https:/`, a typo; `schemed`), dropping a leading `*.`, the fragment, credentials and a slash at the end; anything else (`chrome://`, `file://`, text with spaces, which Chrome's `URL` takes as a host with `%20`s, or the host `https` of `https//example.com`; `named`) is none. `www.` is kept, never stripped, as `www.gov.uk` would widen to `gov.uk`, and "Add this site" on `www.google.com` would cover Gmail. `covers`: the same domain or one under it (`sub.example.com`, not `notexample.com`), or the domain without the site's `www.` (`www.example.com` covers `example.com`, not `news.example.com`), the same port if the site gives one, a segment prefix of the path (`/docs` covers `/docs/guide`, not `/docsy`; paths are case-sensitive), and every parameter of its query among the page's (`youtube.com/watch?v=abc` covers `?t=42&v=abc`). It is stored as its `address` (encoded), shown as its `text` (its domain's labels in their own script, by `Punycode`, RFC 3492's decoding, and the rest `decodeURI`d where it may be), and the lists are `lenient`. The content script (only the top frame's, as Omnibrowser sets no `all_frames`, so `window.location.href` is the address bar's) first waits while the page is left alone (`ignoring(...).find(!_)`), so such a page gets no tooltips, listeners, shared problem or anything else; once started, `readers` gives `None` while it is left alone, so blocking an open page restores it, as a learner change does, keeping the pass numbers going (a fresh `Reader.read` would number its passes from 0 again, colliding with the marks left on the page's nodes). Both re-read on a change of `scope`, either list, or the address, polled each second (`moves`), as a single-page app moves without loading (`whenever`: read at once, then after each trigger, deduplicated): `popstate` misses `pushState`, the isolated world cannot wrap the page's `history`, and `tabs.onUpdated` gives no URL without host access; the poll reads only `location.href`, and storage only when it changes. The content script serves `address` (`location.href`) for its life, even while it waits, so the popup can offer to allow a page left alone. As `moves` and `Highlighter.nodes` tick apart, a single-page app's move into a blocked path could send the new view's text before `readers` hears of it, so each request (`translate`, `hints`, `render`, `define`) first checks the address as it is then (`unlessIgnored`), giving none unasked if the page is left alone: nothing of such a page leaves the browser.
- Each passage's language is found once per pass (`Reader.detect`, 16 passages at once): `omnibrowser-megalingual`'s `languages.detect` on the passage's own text, or, where that is not reliable (short text, and always in Safari, which has no detector), the `lang` of the nearest element (`Highlighter.declared`); a language the browser finds reliably but Megalingual does not know (the module's `Detection.language` is then none) falls back to the `lang` too (`foundLanguage`). The words of each passage found are counted by language for the pass (`Tally`, in `Highlighter.learn`), and once a batch is found, each passage found in none takes the language of most of them (`Highlighter.prevail`), as headings, captions and the like, too short to tell, are in the page's; with no language found at all, a passage counts as in none known, so its words are switched, as a fluent one's are. It is kept on the passage's element (`codeswitchLanguage`, a `Known` of the pass). `choose` takes words only from passages looked at in the pass that the learner `switches` (`switchesFound`), so that one the page put in while the others were being looked at waits for the next tick, rather than being switched as of no language, and perhaps hinted after; and `unread` gives only those in a learnt language that `reads`, each excerpt with its `Learnt`, each passage marked read for the pass (`codeswitchRead`).
- Reading (`Reader.read`): each passage's own text (`Highlighter.own`, a `Passage` in which passages within it are one placeholder, as they are read apart) is cut between sentences (`Words.excerpts`, which segments the text once, and cuts a longer sentence between its words) into excerpts of at most about 100 words (`Reader.nearExcerpts`), or 40 for a passage in sight (`Reader.sightExcerpts`, by `Highlighter.distanceOf` its block, as `unread` takes a size for each), so that the hints for one fit in a reply, and those in sight, each of which is an entry of the streamed reply (below), come soon. Each keeps a live DOM `Range` (`Passage.rangeOf`), which follows it as hints placed in the excerpts before it split its texts, and its hints are placed only within it (`Passage.spanOf`). Excerpts go in `hints` requests nearest first (below), each batch split by its learnt language (`Reader.apart`), so that a request (`Passages`: the `Learnt` and the texts) is of one language, and its prompt names the language and the reader's level in it. Each hint carries its language (`Hint.language`), by which it is rated and looked up. The reply is a list of each passage's entries (`Translator.Marked`, read by Iris, below); one with more or fewer passages is `Problem.unmatchedHints`. The content script turns any failure to find hints into none (`hinting`), keeping why as the page's problem, so that a failed request never stops the pass, which a failed translation does. `Learnt.reads` is false at C2, above which there is nothing, and in Chinese, Japanese and Thai (`spaced`), whose words `Words.occurrences` cannot find, so no hints are asked for them (their words are still counted, below), though words are still switched into them; the popup's note under such a language says why. The model gives entries of the word or phrase, its meaning in `native` (which may give several translations, shown on hovering), its gloss (the one of them that reads in its place, in the form it needs, as models gave lists that broke the sentence when shown inline), whether it is a cognate or loanword the reader would understand as readily as the word of `native` like it (never a false friend), its CEFR level and its dictionary form (below); `Translator.hints` drops cognates, which the level alone marked however transparent (`geomorphologisch`), and keeps the rest above the reader's level (`Learnt.kind`), each then shown as it stands with the reader (`Priority.mark`, below): `Explained` (kept, teal), `Glossed` (replaced by the gloss, or the meaning if it is blank, `codeswitch-gloss`, grey) or `Known`. `Words.place` (pure) quotes each as Annotated Text Format does (a phrase in parts joined by ` … `) and anchors them with `QuotedAnnotation.anchor`: in order, from where the one before begins, as written before in any case or spacing (a hint for `Weg` goes on `Weg` before `weg`), as whole words (not part of a word joined by a hyphen or apostrophe, either apostrophe for either), or else wherever its words occur only once, so a hint given out of order may still be placed; it leaves out what it cannot find, a point, or what overlaps one before. Each is one annotation, its `Marking` saying how it is shown: a phrase in parts (`ruft … an`) is explained in each part, never glossed, and lit together on hovering (`codeswitch-hint-lit`, outlined by `content.css`, as are a translation's pieces, `codeswitch-lit`). A gloss is capitalised only where it begins a sentence (`Words.opens`). `Highlighter.hint` decorates the excerpt's hints at once (`decorate`, under the prefix `codeswitch-hint`, each hint whole or not at all), in a `Try`, so a page that changed under it loses only those hints. Hints hold no draw, so the intensity never hides them.
- Translating whole (`Reader.render`): each passage in a foreign language, not yet read in the pass, is cut into its parts, the text of each of its own text nodes (`Highlighter.foreign`, through `Passage.offsetOf`, as the library's own list of them is private, each at a live `Range`), so that a link's or emphasis's text keeps its element. Into a spaced native language a part leaves the spacing at its ends in the page; into one not spaced it takes it in, so that no space is left between its words. A part longer than `Reader.characters` (2400) is cut between sentences, or else every so many characters (`Words.pieces`), and a passage into stretches of at most that, as a language without spaces counts few words: passages go in `render` requests nearest first, weighed by characters, about 600 in sight, else 2400, a list of each passage's parts in, and out a `Rendition` of each (its `opening`, the passage's first few words untranslated, and its `parts`, as many and in order, both described in its Scaladoc alone), each shown as soon as the model has written it (`Reader.rendering`, below); a passage given back in more or fewer parts is left as it is, one whose opening is not how its passage begins stops the batch, and more or fewer passages is `Problem.unmatchedPassages`. As for hints, a failure translates none not yet shown and keeps why as the page's problem (`Codeswitch.rendering`). `Highlighter.render` puts each part's translation in place of its part, as the page is now (`Passage.spanOf`), as one decoration of the passage (`codeswitch-rendered`, each part whole or not at all, not highlighted but faintly underlined by `renderLook`'s `beneath`), but only parts that still hold what was read (`unchanged`, as `wordOf` checks a word: one text, not left, not rewritten), leaving one given back unchanged as it is, and one given back empty as nothing, but for one within a link, button or label, which keeps its original, as `sparing` keeps their text. Where the page has no space between two parts, as a language without spaces has none, a spaced native language's translation is spaced off the one before, but not before closing punctuation nor after opening (`Words.spacedAfter`). Hovering any part shows the whole passage's original (`Rendered.original`) in a tooltip of its own (`Tips.renderings`, labelled "Original", which the pointer passes through, so its text is cut after a dozen lines rather than scrolled, `Tips.originals`), but for parts within links, buttons and the like, decorated apart and covered by no tooltip, as a tap on one would first show the original rather than follow the link. The intensity does not touch them; restoring and pruning take them out as they do translations and hints.
- The word list (`Familiarity`): over a hint or a translation, the card has a button for each `Answer`, on a scale of five (`point`, 1 to 5, between "Didn't know" and "Knew it", centred on a line of their own, each named "1, Didn't know" and so on): 1 to 3 move the word's familiarity down towards 0, by all, two thirds and a third of `step` (0.15) of the way, 4 ("Mostly knew it") leaves it be, and 5 moves it `step` of the way up towards 1 (`Answer.pull`, `Familiarity.after`), so 0.5 goes to 0.425, 0.45, 0.475, 0.5 or 0.575. The first real press each time the tooltip opens (`answered`; `isTrusted`, so a page's `.click()` does nothing) counts.
  - `FamiliarityService` (in `services/FamiliarityService.scala`) is the one source of every word's familiarity, Alec's rule: a rating and a default are alike to all that reads them. A word's familiarity is its rating (kept in the reader's own database, `familiarity`, `FamiliarityService.Kept`: its `ratings` store, by `Familiarity.nameOf`, `<code>:<word>`, the code of the word's `whole` language, `de` for `de-DE` and `gsw` for Swiss German, so that every variety shares a rating, in the model's case, so `Weg` and `weg`, or Italian and Spanish `burro`, stay apart), or else `Familiarity.default`: from its CEFR level, its difficulty, against the reader's level in its language (`learntIn`, by `alike`), a level above 0.5, further 0.2, at it `known` (0.8), a level below 0.9, further 0.95 (`byLevel`, so that an easy word is hardly ever worth learning, below), and 0.5 where either level is unknown, either moved by the word's evidence (below). `Hint.level` keeps the model's level (`Translator.hintOf`), as `Translation.level` keeps a translation's (`Rendered.level`, of its dictionary form, none for a word declined), and `Headword.level` and `Rating.level` carry it (`Translated.headword`). The background and the popup read it (`of`, `all`, for the Vocabulary tab, `total`), and a page's content script, which cannot reach the extension's IndexedDB, asks the background (`stands`, below); only the background writes, as it answers the `rate`, `seen` and `glance` messages (`Codeswitch.rated`, `sighted`, `glanced`, which, like `define`, refuse a language not being learnt, and bound what a page sends, as `Lookup.checked` does: `Familiarity.checked` trims the word and refuses it blank or over `Lookup.longest`, cuts a sighting's meaning and tip to that, and keeps its word class only if one of `Lookup.wordClasses`; a `seen` message keeps at most `Familiarity.most`, 200, words), one change at a time under `FamiliarityService.lock`, which reads what each word changed holds (`known`) and the sum, then writes them all in one transaction (`writing`, `byWord`), so that the sum of every word's familiarity (the `total` store, under `FamiliarityService.summed`: a `Total` of the `sum` and the `learning` it was counted for, for normalising), kept with each change (`share`: a word rated or seen counts its familiarity, else nothing), is never lost to another tab's. A change of level moves every default without a write, so a `Total` of other levels is counted afresh from every word (`tallied`) before the next write applies.
  - Every word the reader sees shown is kept as seen, rated or not: `Highlighter.hint`, `show` and `reveal` give the `Headword`s they put in sight (placed and not hidden, `shown`), and `Reader` hands them to `Asking.seen`, which sends `seen`; a translation shown only once the intensity rises is seen then. The `sightings` store holds a word's `Sighting` (the level, if ever known, and the word class and meaning where it was last seen, `Familiarity.sighting`), written only when it changes. Nothing evicts sightings, as nothing evicts ratings: every word ever shown stays, a hundred bytes or so each, and each store is read whole whenever every word is read (`all`, and `tallied` counting afresh), as IndexedDB reads a store alone rather than all of local storage. The model gives the dictionary form in each entry (`word`; `Hint.word`; the word itself if blank), and of each translation (`Translation.word`, below). When hints are shown, the content script asks the background how every hinted word stands with the reader (`Asking.stands`, `stands`, `PriorityService.of`), which decides its kind (`Priority.mark`): the words of highest priority are explained (below); of the rest, one threshold (Alec's): from `Familiarity.familiar` (0.5) a word is `Known`, kept with a faint underline (`codeswitch-known`: a transparent highlight, and a 1 px half-opaque teal underline drawn beneath it by the look's `beneath`) and still rateable, else glossed (`Familiarity.kind`). Only words the model gives above the reader's level are marked, so a rated word that it puts at or below their level is not. Both tooltips are interactive (the library's: it stops the pointer's and keys' events at its host, and keeps a press from taking the page's focus), and stays open while the pointer is within the convex hull of the word's line and it, above or below the word; while the mouse that opened it may cross to it, the library covers that hull, but the word and the card, with an invisible bridge, so no other highlight there, not even a neighbour beside the word on its line, which is then half covered, takes the pointer on the way. Its buttons are a labelled group with `aria-pressed`, a row made for each opening, so the first press in the row counts (`Cards.answered`). Each excerpt's hints are one stop of Tab (`Focus.Roving`), the left and right arrow keys moving among them, each showing its tooltip, Tab moving on to its buttons and Enter pressing one; Known words, and hints within links, take no focus, so a long article is not hundreds of stops. Translations take none at all (`Focus.Off`): they are on most pages the reader browses, and the library gives hidden annotations the focus too, so a translation that the intensity hides would be a stop showing nothing; their buttons are reached by the pointer or a tap alone. A tap of a touch or pen shows it too; on a word in a link, a second tap follows the link. A page's own capture listeners on `window` or `document` still see the tooltip's clicks before it stops them, so a page's click-outside handler may still fire.
  - What the reader does with each word shown is a little evidence of how well they know it, kept as simply as Alec asked (no timing): `Glances` (held by `Tips`, given each decoration of hints and translations by `Highlighter`) watches each word of a language being learnt that the page shows, but glosses, whose word it does not show, by an `IntersectionObserver` on its elements, and sends `glance` a `Glanced` (the word, its language and a `Glance`): `Passed` the first time it is in sight while the page is visible and the intensity does not hide it (`look`: on each observation, on `visibilitychange`, and after `Highlighter.reveal`), and `Checked(passed)` the first time its card opens (`Tips.carding`: a hover, a focus or a tap, however brief), taking back the pass if there was one. Each word shown counts once in the page's life, however it is scrolled, but each the page shows is its own (a word shown three times may be passed three times), and a change of the learner, which restores the page, watches anew. The background adds `Glance.evidence` to the word's in the `evidence` store (by its name, as its rating), in log-odds: `passing` (0.01) for a pass, about a thirtieth of "Knew it" at 0.5, and `checking` (0.03) against for a look, about a tenth of "Didn't know", more as it is done on purpose (Alec's). A word's familiarity is its rating or default so moved (`Familiarity.weighed`, the logistic of its log-odds plus the evidence, the same in any order, never reaching 0 or 1), the evidence kept apart from both, so that a change of level still moves a default without a write. A rating rates from the familiarity with its evidence, as the card shows it, and removes the evidence, which the rating then stands for. The evidence is kept apart from the sighting, as each is written by a message of its own. A hover to rate a word counts as a look, and a pass already stood for by a rating (given on another of its occurrences, or in the Vocabulary tab) is still taken back by a later look.
- Frequency and priority (`services/FrequencyService.scala` and `services/PriorityService.scala`, their models in `models/Frequency.scala` and `models/Priority.scala`), each a service beside `FamiliarityService`, at Alec's asking.

Of its senses, `Wiktionary.fitting` finds the one that fits the meaning (`Card.fitting`, by `Card.of` in the background, as `Wiktionary` stays out of the pages): each gloss and the meaning are cut into parts at commas and semicolons, without what is in brackets, each the set of its words of more than two letters (all of them, if it has no other, as `to go` or a run of Han, which `Words.find` takes as one word), less those every part of the entry has; a sense is as close as its closest part to any of the meaning's (Dice's coefficient), a word matching another that it begins, if of at least four letters, with at most three more (`call`, `calls`, `called`, `calling`, as a translation's original is inflected); the closest wins, the first of a tie; none if no word matches, or the entry has one sense. `choose` keeps its own measure, under which `bank` chooses the bank, not the bench whose third sense is a river bank, as the brackets that `fitting` leaves out are what tell those apart. If that cannot be done (no key, a model error, an unreadable reply), they are given in English and none is kept. Where Kaikki has nothing, a model writes the entry (`Translator.defined`, tagging each form only with the tags that `Forms` lays forms out by, `Forms.tags`, so a Finnish noun gets all its cases; single-word forms only, at most 60; and a noun's genders, `Defined.genders`, kept only if of `Entry.genders`), whose forms all count as of a table (`source = Some("model")`); one with no senses is none, and that is kept (`Lexicon.none`, `none:<learnt>:<own>:<class>:<word>`), but a reply that cannot be read fails the lookup like any model error. A `Lexeme`, of no one language (`languages`, of its forms), has its `id` (whole language, word class, etymology, spelling: `de:noun:2:Bank`, by Wiktionary's `etymology_number`, else its place among the entries of its class; a model's is of etymology `0`, so that it is never merged into a dictionary's), `lemma` and `forms` (`Form`: `spelling`, `languages`, `tags`, Kaikki's `table`, which `Forms` needs, and `pronunciations`, each its IPA, its `Recording` and the spelling `marked`), `properties` (genders), `senses` (each definition, and each example's translation, an `Explanation`: a `Version` in each language), `etymologies` and `relations` (semantic on senses, morphological on the lexeme, naming the other word by its spelling). Every claim names its `Source` (`Attributed`), each case a past participle, its fields in one order (who gave it, what from, anything more, then `at`): `Sourced` (dictionary, record URL, time), `Translated` (Iris's `ProviderModel`, from a `Sourced` only, the original text, time), `Generated` (model, `from`, the `Sourced` records it drew on and is credited to, as a model's rewriting of Wiktionary's text is still under its licence, the `Page` read, time) or `Edited` (time, the reader's). `Source.credits` gives the records a claim is credited to (a `Sourced` itself, a translation's original, a generated claim's `from`), `dictionaries` their dictionaries, and `change` the time of the change that made an `Edited` or `Generated` claim (below). A lexeme also keeps `rejected`, what the reader or a review took out (below). A `Spelling` is composed (NFC), without the stress marks that Wiktionary adds to Russian and Ukrainian words (acute and grave) and Bulgarian ones (acute alone, as its grave is spelt in `ѝ`, her), which a form keeps as its pronunciation's `marked`, as the card's tables show them. `Homographs` lists every lexeme spelt alike, and when Wiktionary was asked of that spelling (`checked`, by whole language). The lexicon keeps all of a record's forms and recordings; the card's entry keeps only the forms a card shows (`Forms.kept`) and the recordings a reader of some variety hears (`Wiktionary.audible`, below). Kaikki's senses of `form-of` (`ging`, of `gehen`), and of `alt-of` but not shortened (`abbreviation`, `ellipsis` and the like, as `talo` for `taloyhtiö` is a meaning of its own), only point to another word (`Derivation.pointing`): an entry of no other sense is no lexeme, and `learn` follows each of `Derivation.pointers` (`follow`: learns the lemma, and lists among the spelling's homographs the lemma's lexemes of the pointing entry's class, else all of them), so that a form is counted and looked up as its word; `found` takes the lexemes listed for a spelling that is no lemma, as for `ging`. `Lexicon.entry` `learn`s the word from Kaikki, by its spelling (as Wiktionary names pages without stress marks), unless the spelling was checked (a 404 is kept as checked; a failure keeps nothing), merging each lexeme into what is kept (`Derivation.merged`, below), one change at a time under a `Semaphore`; finds the lexemes whose lemma is the spelling, only those with a dictionary's senses if any have; then, for a reader of another language, puts their English texts into it once (`Derivation.english`, `translated`, `untranslated`), kept as versions; or else generates the word (`Derivation.generated`), kept as the word looked up, though the model wrote it otherwise (`sich freuen` for `freuen`), lest each hover pay to generate it again. Each part of a lookup (fetching, translating, making) asked for again while in flight is waited for, not repeated (`Once`, by the part's name: the record's URL, the lexemes translated, the word generated, so lookups of a word in different senses share one fetch); it is `uncancelable` between registering and starting, `poll`ing the program, lest a cancelled first leave the others waiting for ever.   - A rise draws each text's remaining words again from its mark's level up (`Words.choose`'s `floor`), keeping those shown. `Reader` keeps the intensity in a cats-effect `Ref`, and `Highlighter.nodes` rescans the body on the next one-second tick after a rise, but only once the page is shown (`outOfSight`), so that the tabs in the background don't all ask at once. The first scan of a pass is of the whole body, at once, as a page in a language being learnt has its words counted even at 0%. fs2's `merge`, `concurrently` and `hold1Resource` added 68 KB to the pages' bundle, so keep them out of it.
  - A fall hides the translations above it at once, asking for nothing; a rise back shows them again (`Highlighter.reveal`, by each annotation's `Translated.draw`, through `Decoration.hide` and `show`). `show` hides those whose draws the intensity is not above as soon as they are put in. A hidden part takes the class `codeswitch-hidden` and shows the text it took the place of, and an inserted piece is emptied, its parts kept aside, so that the page's `textContent` is its original text; a hidden translation shows no tooltip. Restoring still gives the page back.
  - A change of intensity never restores the page; a change of the learner does (above).
- Known limits, from the review of #21: `sparing` counts the letters of `textContent`, so a link whose other text is screen-reader-only or a lone arrow can still be emptied to the eye, and it covers only some roles; `<br>` and block children join with no separator in the context; `Passage` is read again for each batch's passage, and its context walked for each text with a word chosen; a run joined by non-breaking spaces counts as one word; code and `.notranslate` text are left out of contexts ("Run `npm install` now" is sent as "Run now"); a framework that writes into the emptied page node gets its text doubled on restore, as before; a word whose space beside it is in a hidden translation's gap is declined, as that space is not in a text node; an excerpt whose live range begins at an element the library put there, rather than a text, may hold that element's text at its start; a copy that the page made of translations is a static clone, which the intensity neither hides nor shows, and only restoring sweeps; and the DOM paths (`settle`, the decorations) are covered only by the end-to-end check and the library's own tests.
- `Tips` holds the two tooltips, Annotated Text Format's `Tooltip`s, each in the page's top layer (or the open modal dialog), its content in a shadow root styled by `Cards.styles`, which the page's styles cannot reach, nor `content.css`; and the `Hovering` that shows each for the element under the pointer (`Tips.carding`), of the decorations added to it, heeding only the user's events (`trusted`). Each (`role="dialog"`, labelled by each card's word) shows the card of its word (`Cards`, above): a hint's, or a translation's, of its dictionary form in the sense of the original it stands for. A hidden translation shows none, as the library gives the tooltip only the annotations shown. Each opens above the line under the pointer if there is room there for a card filled in (`Cards.reserve`, 340 px, as filled cards measured about 320 in their three parts, with a recording's credit, on a page and in the popup alike, against 150 to 210 before), or else below it, kept within the window's sides, and the one the pointer opened keeps to that side (Annotated Text Format's `Tooltip.hold`), scrolling within the room there as its entry or More fills it: one that moved across the line as its entry arrived, as cards near the window's top did, left the pointer crossing to it over the line beyond, whose own card then opened. It closes as the pointer leaves, the page scrolls the line away, or on Escape, which goes on to the page unless the focus opened the tooltip or is in it. Its `:host` rules are `!important`, as the library's own are, or a page's rules for every element (`* { padding: 0 }`) would restyle it; never mark `top`, `left` or `all` so, which would outweigh its placing. A CSS `::after` on the span, as it once was, the page hid for about one word in fifteen: off the top of the window, clipped by `overflow` boxes or covered by sticky headers. `Reader.read` takes the `Tips` that `Tips.shown` makes for the content script's life.
- A word's context is the text around it within its passage (the nearest `p`, `li`, cell, heading, `div`, ...), so that a word in a link or `<em>` still has its sentence; never only its own text node, which for such a word is the word alone. `Highlighter.around` gives it as the page said it: what the library put there as the text it took the place of (`data-annotated-text`), and elements within `skipped` (code, scripts, text fields, `.notranslate`) as a space, so their text is not sent. `Words.context` collapses spacing and keeps 100 characters on each side, or more to reach the ends of the word's sentence, up to 300; `…` marks where either side is cut, and the model is told to decline a word whose translation belongs past one. Sentences come from `Intl.Segmenter` (through a facade in `Words.scala`, using `containing`), or, where there is none (Firefox before 125), from their stops (`Words.byStops`).
- The background never trusts the languages a page's content script names: a `translate` word whose `into`, `hints` passages whose `Learnt`, or a `Lookup` whose `language` is not being learnt (`Learner.learnt`) is declined, given no hints, or refused, and those that are are taken in the language and level the reader stored, so that a stale or rogue page cannot spend the key on other languages; and `render` is answered, unasked, with none while the reader leaves foreign passages.
- The background (`Codeswitch.translations`) reads the key, and asks the chosen model's `PromptService` (`Translator`) for translations of a batch of words with their contexts, each into its own learnt language (`Word.into`), a JSON array of triples in (word, context and the language's English name, the system prompt naming every language of the batch), and out an object for each word (`Rendered`): its pieces (`Placed`: its `text`, with `replacing`, `after` or `before` where it is not shown in the word's place; none to decline), and the translation's dictionary form (`word`, as `aufstehen` of `stehe` and `auf`; the pieces' text if blank) and word class (`wordClass`, kept only if one of `Lookup.wordClasses`), for its card; a declined word keeps neither. `[[ ]]` quoted in a place is dropped, and so is a piece in the word's place that only repeats the word (a model echoing the pairs it was given). A translation is declined (`Translator.fit`) if its pieces have more than `Placement.reach` words in all (a model gave `Bewegen des Mauszeigers über` for `hovering`, though `Placed`'s Scaladoc says three at most), or if it is a determiner's or pronoun's (`det`, `pron`) with a piece replacing a run of more words than the piece has (one gave `die` replacing `the meaning`, which left `meaning` out); a noun's or preposition's may, as Swedish `banken` of `the bank` or German `im` of `in the`. `Rendered.word` and `Placed.replacing` tell the model so too. A reply with more or fewer entries than words, or one for another word than its own (above), is `Problem.unmatched`, as which is which cannot be known: it fails the request like any problem, and the content script, which keeps it as the problem, then leaves every word not yet shown as it is (`Codeswitch.recover`, which knows it by its message, as `Translator` stays out of the pages), as a failed request would end `Reader.pass` for good. The instructions also tell the model never to follow instructions in the contexts. A failure is badged `!` on the toolbar button of the tab that asked (`report`, from `serve`'s `Sender`), or of every tab if none did, and fails the request with the reason explained (`Translator.explain`), which the content script keeps as its tab's `problem` (`noting`, from `MessagingError.reason`) until a translation there succeeds. A success there clears its mark, and so does any change in the popup, for the tab it was opened over.
- Every request is an Iris query of a type (`prompt.query.send`), a stream of them for translations, hints and passages translated whole (`Rendered`, with its `Placed`, `Marked`, `Explained`, `Defined`, private in `Translator`, each `derives Schema`): Iris tells the model its JSON Schema, described by the types' Scaladoc and `@param`s, so write those for the model; reads the reply back; and asks again, three times in all, for one it cannot read, then fails with `QueryError.Unreadable`, as it does at once for a reply cut off at the token limit or stopped by the provider. `explain` makes that `Problem.unreadable`, `cutOff` or `unanswered`, which, like `unmatched` (`Problem.ofBatch`), `recover` takes as a problem of the batch alone, leaving its words as they are and keeping the pass. So the system prompts give only the task, the languages and level, what the input is, and never to follow its instructions; what each field of an answer means, with its examples, is in the types' Scaladoc alone, never repeated in a prompt (Alec's rule), and nothing is parsed by hand. Scaladoc cannot interpolate, so `Placement.reach` (three words), `Lookup.wordClasses`, the form tags and the genders are written out in it, and `TranslatorSuite`'s tests pin them to the code (the form tags to `Forms.tags`, exactly, and the genders to `Entry.genders`, in order) and check that the prompts leave the fields to the schema. A tag added to one of `Forms`' lists must be added to `Inflected`'s Scaladoc too. The types that pages reach (`Level`, `Sense`, `Example`) never derive `Schema` themselves, which would bring Iris into the pages' bundle; `Translator` gives them `Schema.derived`, and `-Xread-docs` (`build.sbt`) has their Scaladoc (`@param`s, for their fields) read even when only `Translator.scala` is recompiled; but an edit to their Scaladoc alone reaches the schemas only once `Translator.scala` is recompiled, as a clean build does. A word class the model gives is kept only if it is one of `Lookup.wordClasses` (`Lookup.wordClass`), which both schemas name, as `Forms.kept` needs `verb` or `noun` exactly.

The popup's key field shows the chosen model's provider's key, and keeps each provider's apart. Any change of settings in the popup clears the badge, and has the content script of the tab it was opened over forget its problem (`dismiss`, ignored where no content script runs).

### Gotchas

- Code Switch says word class (`wordClass`), never part of speech or `pos`, in code, docs and the models' schemas; only Kaikki's JSON names it `pos`, which `Wiktionary` reads as it is.
- A `/*` in a comment, as in a match pattern like `https://*/*`, opens a nested comment in Scala.
- On Windows, if `sbt` cannot start its server, run it with `sbt --server`.
- To build against a local snapshot of Omnibrowser (its `publishLocal`), set `omnibrowserVersion` to it in an uncommitted `.sbt` file, and take the plugin's own `omnibrowser-core` out (`libraryDependencies ~= (_.filterNot(m => m.name == "omnibrowser-core" && m.revision == "0.7.1"))`, at the plugin's version): the plugin adds core at its own version, and `update` refuses the snapshot over it as a possibly incompatible eviction, which neither `dependencyOverrides` nor `libraryDependencySchemes` excuses.
- `Browser.Storage.all` (Omnibrowser 0.8.0) is abstract, so the tests' in-memory `Memory` storage implements it too.
- Run `omnibrowserPackage` in an sbt of its own, not after `testFull` or `omnibrowserBuild` in one invocation: so run, its release link of the content bundle once hung for 15 minutes (`OmnibrowserPlugin.linkContent` awaiting it, no CPU), where alone it takes 20 s. A hung sbt left behind holds the build's boot lock ("server is already booting"), so no other sbt starts there until it is stopped.
- On Windows, a script that rewrites a source file in text mode (as Python's `open(p, 'w')`) writes CRLF. Scalafmt mends the code but not multi-line string literals, such as the model's instructions, which then hold `\r`; write with `newline=''`, and check with `git diff`'s CRLF warning.
- On Windows, if compiling fails with "A required privilege is not held by the client" while backing up a `.sjsir`, delete `target/out/sjs1/**/classes` (sbt 2's disk cache links them) and compile again.
- Git here pushes a branch to its upstream (`push.default=tracking`), and the token may bypass the ruleset that guards `main`. A branch made from `origin/main` tracks `main`, so `git push origin <branch>` lands on `main` without a PR. Make branches with `--no-track`, and push with an explicit target: `git push -u origin HEAD:refs/heads/<branch>`.

## Instructions

### Compilation and Diagnostics

- When the user asks for help with a compilation or type error, start by running `sbt compile` to see the error for yourself.
  If there are many errors, making it unclear which one the user is referring to, ask them to clarify, and then focus only on that issue.
- IntelliJ MCP integration is active. When a request seems to implicitly refer to something the user is looking at, always check
  `mcp__ide__getDiagnostics` first to see which file(s) are open and get associated diagnostics (errors, warnings, and info hints with line numbers).

#### Testing

- After making code changes, always run `sbt compile` to verify that issues are fixed and no new ones are introduced.
- Repeatedly retry upon failure until the build succeeds. If you are unsure how to fix an issue, ask for help or refer to existing code for examples.
- Before trying to fix an error, make sure you first understand it fully.
- You should never report that a feature is complete without testing it first.

### Code Style

- You must read the [Code Style Guidelines](docs/STYLE_GUIDE.md).

### Pull Requests

When asked to publish the code changes, your task is to open one or more pull requests (PRs) to merge the changes into `main` on GitHub:

- Use `git` to check what has changed as compared to the `main` branch on `origin`.
- If the changes are thematically linked, they can be published as a single PR.
- Otherwise, you'll need to divide the changes into multiple PRs using your own judgement.
- Each PR should have a singular focus, shouldn't break anything, and should be able to be merged independently.
- Ensure that all code is staged, committed and pushed. Ensure no new files are left uncommitted, and no debug code is left in the codebase.
- When creating a PR, ensure that the title and description are clear, informative, and comprehensive.
- All feature/bugfix/etc branch names should be formatted as "feature_<short description>" or "fix_<short description>" or similar.
- All PR titles should be formatted as "[<scope>] <Short summary>", e.g. "[renderer] Fixed colour inversion bug."
- Use the `gh` CLI to do the above.

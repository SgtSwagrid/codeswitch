## Project overview

This is a Scala browser plugin that teaches you a language by translating a few words of every page you read.

- It is written with [Omnibrowser](https://github.com/SgtSwagrid/omnibrowser): one object extending `BrowserExtension` defines the plugin, and the `sbt-omnibrowser` plugin (added by the synced `project/plugins-browser-plugin.sbt`) compiles it to JavaScript with Scala.js and lays it out for Chrome and Firefox.
- Its languages are [Megalingual](https://github.com/SgtSwagrid/megalingual)'s `Language`, with their names in every language, flags, tag matching and codec, and its language menus are Megalingual's `LanguagePicker` (`megalingual-laminar`), released dependencies from Maven Central like Iris. A change Code Switch needs in them is made and released in Megalingual. Code Switch adds only `spaced` and `alike` (`Languages.scala`) and `Learner.own`; it never matches on every language.
- It asks a large language model through [Iris](https://github.com/SgtSwagrid/iris), a released dependency from Maven Central (`build.sbt`). A change Code Switch needs in Iris is made in Iris's own repository and released there (its `CLAUDE.md`, *Releases*); then a PR here moves `build.sbt` to that version. Scala Steward proposes new Iris releases here too.
- It puts its translations and hints into pages, and shows their tooltips, through [Annotated Text Format](https://github.com/SgtSwagrid/annotated-text-format)'s `annotated-text-format-dom` (`Passage`, `Decorator`, `Hovering`, `Tooltip`), and finds the hints' passages by its `annotated-text-format-llm` anchoring (`QuotedAnnotation.anchor`): released dependencies from Maven Central like Iris, of one version (`annotatedTextFormat` in `build.sbt`). A change Code Switch needs in them is made and released in Annotated Text Format (to try one first, `publishLocal` it there as a snapshot, its `CLAUDE.md` says how, from a clean checkout of its `main`, not a working copy with another session's changes). Its `TextSpan` is Code Switch's too.
- `sbt omnibrowserBuild` builds it unpacked, for development, under `target/**/omnibrowser/development/<browser>/`, which a browser can load as it is.
  `sbt omnibrowserPackage` zips it for release, under `target/**/omnibrowser/release/`, its bundles minified by esbuild (since Omnibrowser 0.7.0, through `npx`): the main bundle is about 2.22 MB (554 KB gzipped), and the content bundle 1.47 MB (380 KB gzipped). It fails if a file is too large for Firefox Add-ons to parse (5 MiB), which rejected 0.2.0, whose main bundle was 6.49 MB unminified.
- Files in `src/main/extension`, such as icons, are copied into the plugin as they are.
- Versions come from git tags (`v1.2.3` is `1.2.3`), by sbt-dynver. Publishing a GitHub release packages it and attaches the zips (`publish.yml`).

### Architecture

- `Codeswitch` wires the parts, as methods (`background()`, `contentScripts()`, `popup()`): the storage keys (`native`, `fluent`, `learning`, `foreign` and `intensity` in sync storage; `apiKeys`, keyed by `LlmProvider.key`, in local), the tab's `problem` (a `Shared.tab`, which each page's content script owns, so it lasts as long as the page and its badge), the `translate`, `hints` and `render` messages, the `dismiss` tab message, the background that answers them (through `reporting`), the content script and the popup. Only `model` (sync) is on `Translator`, beside the default and codec it is built from.
- Omnibrowser 0.6.0 took circe's codecs, under which a derived enum is stored as `{"Case": {}}`. So `Language` (by its code, Megalingual's codec), `LlmModel` (by `name`) and `Level` (by name) have codecs of their own, which keep each as a plain string; keep them so. The `CodeswitchSuite` and `TranslatorSuite` tests pin the stored forms.
- The reader's languages are in three lists, and every other language is foreign: their own, `native`; the others they read fluently, `fluent` (none by default); and those they are learning, `learning` (none by default), each a `Learnt` with the reader's CEFR `level` in it. `Learner` holds `fluent`, a `NonEmptyList` with the native first (`Learner.native`), and `learning`; `Learner.chosen` makes it from the stored three, each a learnable variety, each once (by root), without a fluent one alike the native. A passage in a fluent language, or in none known, has a share of its words shown in the languages being learnt (`Learner.switches`), each word in one drawn for it (`Learner.into`, each as likely, so that one request holds them all); a passage in a learnt language, in any variety (`Learner.learnt`, which wins over fluency), has its words above the reader's level in it marked, explained in `native`; a passage in any other language, a foreign one, is translated whole into `native` (`Learner.translates`, below), unless the reader chose to leave them (`foreign`: `Foreign.Translate`, the default, or `Leave`, stored by name). A passage in no language known is switched, not translated whole. Nothing is marked while nothing is learnt and foreign passages are left (`Learner.active`), and there are no other switches: each kind of marking is on while its lists have languages. `native` is stored as `None` until the reader chooses it, and is then taken as the first language the browser prefers that is not being learnt, else English (`Learner.own`, from Megalingual's `Browser.preferences`), so that a browser in a learnt language, in any variety (`alike`), does not make it the reader's own; the content script follows the learner (any of its four keys, merged with `parJoinUnbounded`, which costs about 1 KB as `switchMap` already brings parJoin in), deduplicated, and `None` while it is not active. Any change restores the page and starts a new pass, as glosses and hints depend on all of it.
- Each passage's language is found once per pass (`Reader.detect`, 16 passages at once): Omnibrowser's `languages.detect` on the passage's own text, or, where that is not reliable (short text, and always in Safari, which has no detector), the `lang` of the nearest element (`Highlighter.declared`); with neither, it counts as in none known, so its words are switched, as a fluent one's are. It is kept on the passage's element (`codeswitchLanguage`, a `Known` of the pass). `choose` takes words only from passages that the learner `switches`, and `unread` gives only those in a learnt language that `reads`, each excerpt with its `Learnt`, each passage marked read for the pass (`codeswitchRead`).
- Reading (`Reader.read`): each passage's own text (`Highlighter.own`, a `Passage` in which passages within it are one placeholder, as they are read apart) is cut between sentences (`Words.excerpts`, which segments the text once, and cuts a longer sentence between its words) into excerpts of at most about 100 words (`Reader.nearExcerpts`), so that the hints for one fit in a reply. Each keeps a live DOM `Range` (`Passage.rangeOf`), which follows it as hints placed in the excerpts before it split its texts, and its hints are placed only within it (`Passage.spanOf`). Excerpts go in `hints` requests nearest first (below), each batch split by its learnt language (`Reader.apart`), so that a request (`Passages`: the `Learnt` and the texts) is of one language, and its prompt names the language and the reader's level in it. Each hint carries its language (`Hint.language`), by which it is rated and looked up. The reply is a list of each passage's entries (`Translator.Marked`, read by Iris, below); one with more or fewer passages is `Problem.unmatchedHints`. The content script turns any failure to find hints into none (`hinting`), keeping why as the page's problem, so that a failed request never stops the pass, which a failed translation does. `Learnt.reads` is false at C2, above which there is nothing, and in Chinese, Japanese and Thai (`spaced`), whose words `Words.occurrences` cannot find, so nothing is sent for them, though words are still switched into them; the popup's note under such a language says why. The model gives entries of the word or phrase, its meaning in `native` (which may give several translations, shown on hovering), its gloss (the one of them that reads in its place, in the form it needs, as models gave lists that broke the sentence when shown inline), whether it is a cognate or loanword the reader would understand as readily as the word of `native` like it (never a false friend), its CEFR level and its dictionary form (below); `Translator.hints` drops cognates, which the level alone marked however transparent (`geomorphologisch`), and keeps the rest above the reader's level, as `Learnt.kind` bands them: one level up is `Explained` (kept, teal), further up `Glossed` (replaced by the gloss, or the meaning if it is blank, `codeswitch-gloss`, grey). `Words.place` (pure) quotes each as Annotated Text Format does (a phrase in parts joined by ` … `) and anchors them with `QuotedAnnotation.anchor`: in order, from where the one before begins, as written before in any case or spacing (a hint for `Weg` goes on `Weg` before `weg`), as whole words (not part of a word joined by a hyphen or apostrophe, either apostrophe for either), or else wherever its words occur only once, so a hint given out of order may still be placed; it leaves out what it cannot find, a point, or what overlaps one before. Each is one annotation, its `Marking` saying how it is shown: a phrase in parts (`ruft … an`) is explained in each part, never glossed, and lit together on hovering (`codeswitch-hint-lit`, outlined by `content.css`, as are a translation's pieces, `codeswitch-lit`). A gloss is capitalised only where it begins a sentence (`Words.opens`). `Highlighter.hint` decorates the excerpt's hints at once (`decorate`, under the prefix `codeswitch-hint`, each hint whole or not at all), in a `Try`, so a page that changed under it loses only those hints. Hints hold no draw, so the intensity never hides them.
- Translating whole (`Reader.render`): each passage in a foreign language, not yet read in the pass, is cut into its parts, the text of each of its own text nodes (`Highlighter.foreign`, through `Passage.offsetOf`, as the library's own list of them is private, each without the spacing at its ends, at a live `Range`), so that a link's or emphasis's text keeps its element. Passages go in `render` requests nearest first, about 100 words in sight, else 300, a list of each passage's parts in, and out a `Rendition` of each (its `parts`, as many and in order, described in its Scaladoc alone); a passage given back in more or fewer parts is left as it is, and more or fewer passages is `Problem.unmatchedPassages`. As for hints, a failure translates none and keeps why as the page's problem (`Codeswitch.rendering`). `Highlighter.render` puts each part's translation in place of its part, as the page is now (`Passage.spanOf`), as one decoration of the passage (`codeswitch-rendered`, each part whole or not at all, not highlighted but faintly underlined by `renderLook`'s `beneath`), leaving a part given back unchanged or empty as it is; hovering any part shows the whole passage's original (`Rendered.original`) in a tooltip of its own (`Tips.renderings`, labelled "Original", which the pointer passes through). The intensity does not touch them; restoring and pruning take them out as they do translations and hints.
- The word list (`Familiarity`): over a hint or a translation, the card has a button for each `Answer` (Knew it 1.0, Unsure 0.6, Didn't know 0.0). The first real press each time the tooltip opens (`answered`; `isTrusted`, so a page's `.click()` does nothing) moves the word's familiarity `step` (0.15) of the way to its mark, from where its hint's kind puts an unrated word (explained 0.5, glossed 0.2), as its `Marking.hint` keeps it, so a split phrase starts from its own level, not from its being explained; a translated word starts as explained, as a translation has no level (`Translated.headword`), and its rating counts only in the reading mode, as nothing in translating uses it. Each word has a local key of its own, `familiarity:<code>:<word>` (`Familiarity.key`, by the root code of the hint's language, `Rating.language`, `de` for `de-DE`, so that every variety shares a rating, and a language stored as a whole one is rated and read under one key), in the model's case, so `Weg` and `weg`, or Italian and Spanish `burro`, stay apart, and a rating never rewrites another's; two tabs rating the same word at the same moment could still lose one. The model gives the dictionary form in each entry (`word`; `Hint.word`; the word itself if blank), and of each translation (`Translation.word`, below). When hints are shown, the content script reads the familiarity of each hinted word (`Codeswitch.familiarities`), and a rated word's decides its kind in place of its level (`Familiarity.apply`): from 0.8 it is `Known`, kept with a faint underline (`codeswitch-known`: a transparent highlight, and a 1 px half-opaque teal underline drawn beneath it by the look's `beneath`) and still rateable, above 0.35 explained, else glossed. Only words the model gives above the reader's level are marked, so a rated word that it puts at or below their level is not. Nothing else is tracked. Both tooltips are interactive (the library's: it stops the pointer's and keys' events at its host, and keeps a press from taking the page's focus), and stays open while the pointer crosses from the word's line to it, above or below the word. Its buttons are a labelled group with `aria-pressed`, a row made for each opening, so the first press in the row counts (`Cards.answered`). Each excerpt's hints are one stop of Tab (`Focus.Roving`), the left and right arrow keys moving among them, each showing its tooltip, Tab moving on to its buttons and Enter pressing one; Known words, and hints within links, take no focus, so a long article is not hundreds of stops. Translations take none at all (`Focus.Off`): they are on most pages the reader browses, and the library gives hidden annotations the focus too, so a translation that the intensity hides would be a stop showing nothing; their buttons are reached by the pointer or a tap alone. A tap of a touch or pen shows it too; on a word in a link, a second tap follows the link. A page's own capture listeners on `window` or `document` still see the tooltip's clicks before it stops them, so a page's click-outside handler may still fire.
- The dictionary, for the card in each tooltip (`Cards`, below): the `define` message takes a `Lookup` (a word's dictionary form, part of speech, meaning and language: a hint's, or the original that a translation stands for and the language it was translated into, `Word.into`, kept on its `Translated`, the meaning cut to `Lookup.longest`; `Lookup.checked` trims it, drops a part of speech not in `Lookup.parts`, and refuses an empty or over-long one, as a page's content script may send anything) and gives a `Card`: an `Entry`, in Wiktionary's shape (senses with glosses and examples, forms tagged as Wiktionary tags them, IPA, etymology, `Source`), with its principal forms and tables laid out by the background (`Card.of`, so `Forms` stays out of the pages' bundle) and the Wiktionary page it is from (`Wiktionary.page`, `en.wiktionary.org/wiki/<word>#<Kaikki's name>`), which the card credits (CC BY-SA). The background looks the word up in its `language`, explained in the reader's `native` (`Dictionary.entry`, `Translator.explained` and `defined` take the native, not a `Learner`), and a card's word is rated in its language (`Headword.language`). The hints' and translations' parts of speech are checked against `Lookup.parts` too. Words from pages, and Wiktionary's text, go only in a request's user message, never its system prompt.
  - Kaikki: `Wiktionary.url` is `kaikki.org/dictionary/<name>/meaning/<1st letter>/<1st two>/<word>.jsonl`, of the word composed (NFC) with `.` as `_dot_` and `/` as `_slash_`, the folders taken from that (`z. B.` is at `z/z_/z_dot_ B_dot_.jsonl`), each part percent-encoded. Kaikki has dictionaries of whole languages, so `<name>` is the root's (`lineage.last`) English name, as Megalingual gives it, but Norwegian (`nb`) is "Norwegian Bokmål", Croatian and Serbian "Serbo-Croatian", Filipino "Tagalog" and Slovenian "Slovene" (`Wiktionary.nameOf`); a test checks every root against Kaikki's index (`src/test/resources/kaikki/languages.txt`). Paths are case-sensitive. Kaikki sends no CORS headers, so the background needs a host permission for it, `Wiktionary.host` in `hosts`, required. It asks nothing more of a reader who updates: the content scripts' `http://*/*` and `https://*/*` already give Chrome's one warning, "Read and change all your data on all websites", with or without it (checked with `chrome.management.getPermissionWarningsByManifest` from the worker, which needs no permission). `Dictionary.read`: a 404 is no entry, any other failure (offline, 429, 5xx) fails the lookup and keeps nothing.
  - An entry's `genders` are those of `Entry.genders` (masculine, feminine, neuter, common, in that order) that every glossed sense is tagged with (`Wiktionary.agreed`), as Kaikki tags each sense with its heading's gender (`Bank f`, `дом m inan`); several (Spanish `mar`) if each sense has several, none if the senses disagree, and none for a verb. Animacy (`inanimate`, Polish `animal-not-person`) is not kept. `Translator.explained` is not sent them, and keeps them (`explainedAs` copies the entry).
  - Of a word's entries (one per etymology, as `Bank` the bench and `Bank` the bank), `Wiktionary.candidates` keeps those with senses, of its part of speech if any are, at most four, and `choose` takes the one whose best gloss most fits the meaning, by the share of the gloss's words in it. The glosses are English, so for a reader of another language all the candidates are first put into theirs in one request (`Translator.explained`: glosses, translations and etymology; the reply must have as many entries, senses and examples, and the examples' text is kept as Wiktionary's), then chosen among. If that cannot be done (no key, a model error, an unreadable reply), they are given in English and not kept. A kept translation is used only if it still `fits` the entry in its place (word, part of speech, number of senses), as Kaikki may reorder a word's entries. Where Kaikki has nothing, a model writes the entry (`Translator.defined`, tagging each form only with the tags that `Forms` lays forms out by, `Forms.tags`, so a Finnish noun gets all its cases; single-word forms only, at most 60; and a noun's genders, `Defined.genders`, kept only if of `Entry.genders`), whose forms all count as of a table (`source = Some("model")`); one with no senses is none, and kept, but a reply that cannot be read fails the lookup like any model error. The model's client is asked for only then (`Dictionary.Ask`), so a word Wiktionary has needs no key for an English reader.
  - The cache, local, word last in each name so no word can pass for another: Kaikki's entries for a word, `wiktionary:<learnt>:<word>` (none kept for a 404); each candidate put into the reader's language, `explained:<learnt>:<own>:<index>:<word>`; a model's entry, `made:<learnt>:<own>:<pos>:<word>`, `<learnt>` the root code of the lookup's language (`de` for `de-DE`) and `<own>` the reader's variety's (`en-GB`), as they explain in it. A reader of any English (`alike`) gets Wiktionary's English as it is (kept even if none, as asking again costs as much). Only the `Dictionary.capacity` (300) latest used are kept, their names in `dictionary`, latest first, changed under a `Semaphore` (`Semaphore.in[SyncIO, IO]`, as the background has no resource to hold one; a test with slow storage fails without it); the list is written before the value, so that nothing is kept unlisted, and a write that fails, as when storage is full, is ignored. Each part of a lookup (fetching, translating, making) asked for again while in flight is waited for, not repeated (`Once`, by the part's cache name, so lookups of a word in different senses share one fetch); it is `uncancelable` between registering and starting, `poll`ing the program, lest a cancelled first leave the others waiting for ever. A model request that failed is not made again for `Dictionary.pause` (a minute; `unlessFailed`, `noting`), its failure given meanwhile; only requests made are noted, inside `Ask`'s `use`, so a missing key is not, and a key just given is used at once. `forgetFailures` clears them between tests. Entries keep only the forms a card shows (`Forms.kept`).
  - `Forms` (pure) lays forms out, the same way in every language, as Wiktionary tags them alike. Only the forms of a source's first table count (`Wiktionary.firstTables`: each table begins with a `table-tags` form), which leaves out Spanish forms with clitics and the reflexive, German subordinate-clause and compound tenses, and Russian spellings from before 1918; then none tagged `combined-form`, `multiword-construction`, possessive or `object-*`, nor dashes or pronunciations (French tables give IPA). A verb's rows are number, then person, or else gender (a Russian past), the singular first, as dictionaries lay them out; its columns are the known tense and mood tags (a tense without a mood is indicative; `negative` makes its own column), named in a fixed order, a tense left out of the name where no other column has its mood. If any column has a single-word form, columns of only several words (compound tenses with an auxiliary, as Finnish has for each) are left out; a separable verb's are all of several words, so German `rufe an` is kept. Participles, infinitives and gerunds are principal forms, not rows. Tables are laid out only for the languages and parts of speech checked against real files (`Forms.checked`: verbs of German, Spanish, Italian, Portuguese, French, Finnish and Russian; nouns of German, Finnish, Russian, Turkish and Polish), by the root, so a variety counts; others (Dutch, with no person in the plural; Swedish and Danish, with none at all; Polish verbs, with genders beside persons; Hungarian's definite conjugation; Turkish verbs) have their principal forms alone, and only those are kept. Add a language only with a fixture and tests of its tables. A noun's rows are every case it has (Finnish has 14), against number, without forms of several words (as with an article) unless all are. The tests read real Kaikki files in `src/test/resources/kaikki` (through `Kaikki`, with Node's `fs`, each file's language from its `lang_code`), of German, Spanish, Italian, Portuguese, French, Finnish, Russian, Turkish, Polish and Dutch words.
  - Checked against live Kaikki in Chrome by sending `{omnibrowser: "define", request}` with `chrome.runtime.sendMessage` from the popup page.
  - The card (`Cards`, made by `Tips` for both tooltips, labelled by its word and part of speech, `Cards.label`) is of a `Headword` (`Marking.headword`, `Translated.headword`), and shows at once its dictionary form and part of speech, its tip (a translation's original, or a hint's; left out where it is the dictionary form, as a gloss's original may be) and the rating buttons; then, once the tooltip has stayed open `Cards.patience` (300 ms) and `Showing.isCurrent`, so a pointer passing over hints looks nothing up, it says "Looking up…" and asks `define`, and fills in: the genders after the part of speech, muted like it (`Cards.grammar`: `noun, feminine`, `noun, masculine or feminine`), IPA, principal forms, the first three senses' glosses, and the credit, after the buttons, so Tab reaches them first. **More** (`aria-expanded`) toggles the card's `detailed` class, under which CSS shows the other senses, the examples (two a sense), the tables (each in a `.scroll` box, as a verb's are wide) and the etymology; the next card opens as the last was left, for the page's life, and More appears only if there is more (`Cards.more`). Hidden parts hold nothing focusable, as the library's Tab handling would focus one. It fills in place, not by `Showing.update`, so a rating pressed while it loads, and the focus, survive, and the library places it again as it grows (a `ResizeObserver`); above the line, it grows upward, so More stays under the pointer. Each lookup that succeeded is kept in the page (`Cards.found`) and fills the next card at once, as `browser.run` runs it up to its first asynchronous step before the tooltip shows; a failure (`define`'s reason, through `Codeswitch.reason`) or no entry is said in the card and not kept. Content is built with `textContent`, never HTML, as it is the page's, Wiktionary's or a model's.
- Pages load their own bundle, `omnibrowser-content.js`, holding only what `contentScripts()` and `Codeswitch`'s own values reach; the main `omnibrowser.js` is for the background and popup. So `Codeswitch`'s values must not reach Iris or `Translator` (`model`'s codec and default reach Iris's model lists, and `hosts` is a `def` for `LlmProvider`): put what only the background or popup needs in their methods or on `Translator`. The sizes here are of the content bundle unminified, as the linker gives it (`target/out/sjs1/scala-3.9.0/codeswitch/codeswitch-opt-content/omnibrowser-content.js`, beside the release's minified copy in `codeswitch-opt-content-minified`); measure each package's share there, by the definitions' names (`$c_Lcom_alecdorrington_…`), which minifying shortens. The card (`Cards`, `Card`'s codecs) adds 17 KB (4.7 KB gzipped) to the minified release, against a build of main's sources, as minified names cannot be told apart; check `Forms` and `Wiktionary` stay out (none of `Forms`' table titles, as `Declension`, should be in it). It is about 4.05 MB (589 KB gzipped): Annotated Text Format's `dom` took it from 3.64 MB (533 KB gzipped, with its `llm` 0.2.0 for anchoring) with 267 KB of its own, 79 KB of Scala's collections and 32 KB of Cadmus (which its core 0.3.0 depends on), less 28 KB of Code Switch's own. The greps below work on the release bundles too, as minifying keeps the classes' names in strings. Earlier, it was about 3.39 MB (499 KB gzipped); Megalingual's `Language` and its tag matching added 82 KB (5.5 KB gzipped) over Code Switch's own, measured against main's 3.31 MB. Nothing of Laminar, nor Megalingual's names or flags (which only `name`, `title` and `flag` reach), may reach it: `grep -oE 'com\.raquo\.[a-z]*|megalingual\.names'` on it should find nothing. With the `define` message's codecs, which pages will need for the card, it is about 3.44 MB. Before, it was about 3.25 MB (the word list adds 20 KB): circe's codecs (Omnibrowser 0.6.0) took it from 2.82 MB to 3.12 MB, and the reading mode adds 114 KB (13 KB gzipped). It was 3.89 MB when pages loaded the main bundle; `grep -o 'com\.alecdorrington\.iris\.[A-Za-z]*'` on it should find nothing.
- The content script (`Reader`) watches the learner and, for each in turn (`switchMap`), restores the page, then marks its body and every node added to it, a pass at a time. `Highlighter` does all Code Switch's DOM work: it chooses words in text nodes (marking each node with the pass and the intensity its words were drawn up to, which each text that the library splits off it copies, through `Decorator.decorate`'s `split`, so that its words are not drawn again), and shows each word's translation as its model laid it out (below). Annotated Text Format's `Decorator` puts each into the page, each piece a `span.codeswitch` holding the text it took the place of in `data-annotated-text` (`Passage.decorated`) and its annotations' indices in `data-codeswitch`, highlighted by the library in the colour of `Highlighter`'s `Look`, and given its cursor by `src/main/extension/content.css` (put in every page by the manifest, through `withCss`). `Highlighter` keeps the decorations of the pass, to reveal and restore them; on each scan of the page (`Reader.pass`, before detecting), `Highlighter.prune` restores and forgets those of which no element is in the page any more, as of passages an infinite-scroll page or single-page app took out, and stops the `Hovering`s covering them, so they do not pile up.
- What the reader sees is asked for first (`Words.nearestFirst`, pure, by `Highlighter.distance`: how far a range's box is from the window, across and down, `0` in sight, infinite with no box): words in sight in batches of 10 (`Reader.nearBatch`), and excerpts in sight in `hints` requests of about 100 words, then the rest, nearest first, in batches of 40 words, or requests of about 300; each batch in the page's order. Words are batched one by one, as each keeps a live range, so a paragraph's words may go in several batches (a paragraph's words kept together made a batch in sight as large as the paragraph's share). A model writes its reply a word at a time, so a reply's time grows with its batch: a batch of 40 took 10 to 15 s, which left the page as it was meanwhile. Six requests of each kind go at once (`Reader.parallel`). Rate limits are per minute, so the number of requests, which this leaves about as it was, matters more than how many go at once.
- A translation (`Translation`, in `Placement.scala`) is a list of `Piece`s, each with a `Place`: the word's own (`Home`), a run of up to `Placement.reach` words around it (`Replacing`, as an article with its noun), or beside a quoted anchor (`After`/`Before`, as a German verb at the end of its clause); several pieces split a word (a separable verb), and none declines it. It keeps the translation's dictionary form and part of speech too (`word`, `pos`), for its card. `Placement.lay` (pure, tested in Node) finds the places in the passage's text: a run within the word's own text node, of at most `reach` words split at spaces and with no digits; an anchor's nearest occurrence within the word's sentence, as a whole word (`Words.occurrences`: not part of a word joined by a hyphen or apostrophe, either apostrophe for either). Any piece without a place declines the whole translation, and so does one that would take the last letters of a link, button or label, with those of the batch before it (`Highlighter.sparing`). A `Layout` is one annotation (`Layout.parts`: its home, and a point for each place pieces go, those at one point joined by spaces), its value a `Translated`, which gives what each part shows, the original, the draw, and the translation's dictionary form and part of speech.
- If no piece stays in the word's place, its place shows nothing (an empty `span.codeswitch`), and the space beside it becomes an empty `span.codeswitch-gap` (the library's `Spacing.besides`: after it, else before it, each emptied word its own, handed out from the last back, so that "what I have seen." with both moved in one batch reads "what I."; perhaps in the next text node, as for a word alone in `<em>`; never a line break, which `pre-wrap` keeps), so that no two spaces are left together. A moved piece is a `span.codeswitch-inserted` holding its `span.codeswitch` and the spaces that `Spacing.around` gives it. `Decoration.restore` takes out each inserted span and puts back the text each other took the place of, which must give the page's text exactly. `Highlighter.restore` then sweeps the page for any of ours left (`[data-annotated-text][class^=codeswitch]`), as copies a page made of them (a carousel, `innerHTML`), which no decoration knows of, and puts their `data-annotated-text` in their place.
- `Choice` keeps its word as a live DOM `Range`, which follows the word as other translations split its text node, and is checked against the word before showing. A live range that begins where an element is inserted keeps beginning at the end of the text before it, so the element falls within it: `wordOf` first moves such a start to the next text with prose (`settle`).
- `show` groups each batch's choices by passage, each passage in a `Try`, and lays each translation out in its `Passage` as it is then (`Highlighter.entire`): the library's, in which each element within `skipped` is one U+FFFC, each `<br>` and boundary between blocks a line break, and each element it put there reads as what it shows (a gap as nothing, or its space while hidden; a hidden inserted piece as nothing), so that "what I have seen." with both moved, the earlier shown first (as words from separate batches or rescans may be), reads "evah nees what I.". The passage's translations go in as one decoration, `whole`: one that cannot all be shown, as over what another shows, is left out. They are given from the last word back, as the library keeps the first of two that overlap, so the later wins, as a noun replacing its article does over the article alone, as before.
- The library's edits split a text node only within it, never at its ends; a replacement at a node's start leaves the page's node itself, empty, after the element, as a page or framework may hold on to it. It records the page's text that each node it split off or put in place came from (one `WeakMap` for every decoration), and its `restore` joins each run of them still side by side back into it, so the page keeps its own text nodes, whole, even if a page script has since put something between them; decorations may be restored in any order.
- The intensity (0 to 40%, 5% by default, from the popup's slider) is the share of words translated. Each word is drawn a number from 0 to 1 and is translated while the intensity is above it, so changing it never redraws the page:
  - A rise draws each text's remaining words again from its mark's level up (`Words.choose`'s `floor`), keeping those shown. `Reader` keeps the intensity in a cats-effect `Ref`, and `Highlighter.nodes` rescans the body on the next one-second tick after a rise, but only once the page is shown (`outOfSight`), so that the tabs in the background don't all ask at once. fs2's `merge`, `concurrently` and `hold1Resource` added 68 KB to the pages' bundle, so keep them out of it.
  - A fall hides the translations above it at once, asking for nothing; a rise back shows them again (`Highlighter.reveal`, by each annotation's `Translated.draw`, through `Decoration.hide` and `show`). `show` hides those whose draws the intensity is not above as soon as they are put in. A hidden part takes the class `codeswitch-hidden` and shows the text it took the place of, and an inserted piece is emptied, its parts kept aside, so that the page's `textContent` is its original text; a hidden translation shows no tooltip. Restoring still gives the page back.
  - A change of intensity never restores the page; a change of the learner does (above).
- Known limits, from the review of #21: `sparing` counts the letters of `textContent`, so a link whose other text is screen-reader-only or a lone arrow can still be emptied to the eye, and it covers only some roles; `<br>` and block children join with no separator in the context; `Passage` is read again for each batch's passage, and its context walked for each text with a word chosen; a run joined by non-breaking spaces counts as one word; code and `.notranslate` text are left out of contexts ("Run `npm install` now" is sent as "Run now"); a framework that writes into the emptied page node gets its text doubled on restore, as before; a word whose space beside it is in a hidden translation's gap is declined, as that space is not in a text node; an excerpt whose live range begins at an element the library put there, rather than a text, may hold that element's text at its start; a copy that the page made of translations is a static clone, which the intensity neither hides nor shows, and only restoring sweeps; and the DOM paths (`settle`, the decorations) are covered only by the end-to-end check and the library's own tests.
- `Tips` holds the two tooltips, Annotated Text Format's `Tooltip`s, each in the page's top layer (or the open modal dialog), its content in a shadow root styled by `Cards.styles`, which the page's styles cannot reach, nor `content.css`; and the `Hovering` that shows each for the element under the pointer (`Tips.carding`), of the decorations added to it, heeding only the user's events (`trusted`). Each (`role="dialog"`, labelled by each card's word) shows the card of its word (`Cards`, above): a hint's, or a translation's, of its dictionary form in the sense of the original it stands for. A hidden translation shows none, as the library gives the tooltip only the annotations shown. Each opens above the line under the pointer (below it in the window's top line, and kept within its sides), and closes as the pointer leaves, the page scrolls the line away, or on Escape, which goes on to the page unless the focus opened the tooltip or is in it. Its `:host` rules are `!important`, as the library's own are, or a page's rules for every element (`* { padding: 0 }`) would restyle it; never mark `top`, `left` or `all` so, which would outweigh its placing. A CSS `::after` on the span, as it once was, the page hid for about one word in fifteen: off the top of the window, clipped by `overflow` boxes or covered by sticky headers. `Reader.read` takes the `Tips` that `Tips.shown` makes for the content script's life.
- A word's context is the text around it within its passage (the nearest `p`, `li`, cell, heading, `div`, ...), so that a word in a link or `<em>` still has its sentence; never only its own text node, which for such a word is the word alone. `Highlighter.around` gives it as the page said it: what the library put there as the text it took the place of (`data-annotated-text`), and elements within `skipped` (code, scripts, text fields, `.notranslate`) as a space, so their text is not sent. `Words.context` collapses spacing and keeps 100 characters on each side, or more to reach the ends of the word's sentence, up to 300; `…` marks where either side is cut, and the model is told to decline a word whose translation belongs past one. Sentences come from `Intl.Segmenter` (through a facade in `Words.scala`, using `containing`), or, where there is none (Firefox before 125), from their stops (`Words.byStops`).
- The background never trusts the languages a page's content script names: a `translate` word whose `into`, `hints` passages whose `Learnt`, or a `Lookup` whose `language` is not being learnt (`Learner.learnt`) is declined, given no hints, or refused, and those that are are taken in the reader's stored variety and level, so that a stale or rogue page cannot spend the key on other languages; and `render` is answered, unasked, with none while the reader leaves foreign passages.
- The background (`Codeswitch.translations`) reads the key, and asks Iris's `LlmClient` (`Translator`) for translations of a batch of words with their contexts, each into its own learnt language (`Word.into`), a JSON array of triples in (word, context and the language's English name, the system prompt naming every language of the batch), and out an object for each word (`Rendered`): its pieces (`Placed`: its `text`, with `replacing`, `after` or `before` where it is not shown in the word's place; none to decline), and the translation's dictionary form (`word`, as `aufstehen` of `stehe` and `auf`; the pieces' text if blank) and part of speech (`pos`, kept only if one of `Lookup.parts`), for its card; a declined word keeps neither. `[[ ]]` quoted in a place is dropped, and so is a piece in the word's place that only repeats the word (a model echoing the pairs it was given). A reply with more or fewer entries than words is `Problem.unmatched`, as which is which cannot be known: it fails the request like any problem, and the content script, which keeps it as the problem, then leaves every word as it is (`Codeswitch.recover`, which knows it by its message, as `Translator` stays out of the pages), as a failed request would end `Reader.pass` for good. The instructions also tell the model never to follow instructions in the contexts. A failure is badged `!` on the toolbar button of the tab that asked (`report`, from `serve`'s `Sender`), or of every tab if none did, and fails the request with the reason explained (`Translator.explain`), which the content script keeps as its tab's `problem` (`noting`, from `MessagingError.reason`) until a translation there succeeds. A success there clears its mark, and so does any change in the popup, for the tab it was opened over.
- Every request is Iris's `ask` of a type (`Rendered`, with its `Placed`, `Marked`, `Explained`, `Defined`, private in `Translator`, each `derives Structured`): Iris tells the model its JSON Schema, described by the types' Scaladoc and `@param`s, so write those for the model; reads the reply back; and asks again, three times in all, for one it cannot read, then fails with `LlmError.Unreadable`, as it does at once for a reply cut off at the token limit or stopped by the provider. `explain` makes that `Problem.unreadable`, `cutOff` or `unanswered`, which, like `unmatched` (`Problem.ofBatch`), `recover` takes as a problem of the batch alone, leaving its words as they are and keeping the pass. So the system prompts give only the task, the languages and level, what the input is, and never to follow its instructions; what each field of an answer means, with its examples, is in the types' Scaladoc alone, never repeated in a prompt (Alec's rule), and nothing is parsed by hand. Scaladoc cannot interpolate, so `Placement.reach` (three words), `Lookup.parts`, the form tags and the genders are written out in it, and `TranslatorSuite`'s tests pin them to the code (the form tags to `Forms.tags`, exactly, and the genders to `Entry.genders`, in order) and check that the prompts leave the fields to the schema. A tag added to one of `Forms`' lists must be added to `Inflected`'s Scaladoc too. The types that pages reach (`Level`, `Sense`, `Example`) never derive `Structured` themselves, which would bring Iris into the pages' bundle; `Translator` gives them `Structured.derived`, and `-Xread-docs` (`build.sbt`) has their Scaladoc (`@param`s, for their fields) read even when only `Translator.scala` is recompiled; but an edit to their Scaladoc alone reaches the schemas only once `Translator.scala` is recompiled, as a clean build does. A part of speech the model gives is kept only if it is one of `Lookup.parts` (`Lookup.part`), which both schemas name, as `Forms.kept` needs `verb` or `noun` exactly.
- The reader chooses any model Iris lists (`Translator.models`, by provider; Claude Haiku 4.5 by default), kept by `LlmModel.name` (`given Codec[LlmModel]` in `Translator`), and gives a key for its provider. The popup's key field shows the chosen model's provider's key, and keeps each provider's apart. Any change of settings in the popup clears the badge, and has the content script of the tab it was opened over forget its problem (`dismiss`, ignored where no content script runs).
- Code outside `Codeswitch` that uses `browser.storage` needs `(using Granted[Storage])`, as the grant is only given inside the extension object.
- The popup is rendered by Laminar (`LaminarPage`, from `omnibrowser-laminar`) and styled by `src/main/extension/popup.css` (`withStylesheets`). The fourth section, "Other languages", is two radio buttons (`foreigns`, `choice`, named `foreign`, stored through `saver` on `change`): "Translate into <native>", the default, and "Leave untranslated". Each list is a `field` (a `group` named by its heading, with a note under it, rather than a `label`, which would pass a click on a choice to a picker's button): "Native language", a Megalingual `LanguagePicker` leading with each language's own name; then "Other fluent languages" and "Languages to learn", each its languages (flag, name and a × button, `removing`, named "Remove French"), rendered by `splitSeq` on the language, so a level change keeps its menu, above an `optional` picker that adds one (`adding`, whose "None" reads "Add a fluent language"); the intensity is between them. Each learnt language has its own level `menu`, showing the level's code alone, so that the name has room, described by the note under it (`described`, linked by `aria-describedby`: the level's description, and why nothing is marked at C2 or where its words are not spaced, `unmarked`). A picker offers only the languages in none of the three lists (`placed`, `offered`, by `alike`), so that the lists stay apart; as a picker offers those it is made with, each is made again when the lists change (the native one only when the other two do, so that choosing in it keeps it). As pickers and × buttons fire no input event, their observers also clear the problem (`chosen`). A picker made again would drop the keyboard's focus, so an adding picker takes it once made again after it added a language, or the last of its list was taken out (`refocusFluent`, `refocusLearning`); a × button first hands it to the next language's ×, or the one before (`handOn`). Choosing "None" in an adding picker saves nothing. `popup.css` gives the pickers the popup's colours through `--megalingual-*` properties. The other selects are `menu`s, but the models', which has groups. Stored settings come in as signals (`browser.signal(key)`), and the problem as the active tab's shared value (`browser.signal(Codeswitch.problem, tab)`, through `flatMapSwitch` on the active tab). The native picker and the model's menu store their choices through `saver(key)`, and the lists' changes through `saving` an update of the list (`storage.update`); the slider stores through `saver` too, on `change` (letting it go, or each key press), but not while a key held down repeats (`held`), when it stores only on `keyup`, as sync storage allows 120 writes a minute; never throttle it, as a timer's trailing write dies with the popup. It shows its value on `input`, which it stops from bubbling up, and ignores the stored value while it has focus, lest a step stored late move it back. The key field stores through `saving`, which wrap `browser.observer` so that the popup's foot shows its status: a spinner while any change is saving (for at least 500 ms, as a write is too quick to see, so typing keeps it spinning), then a tick and "Saved", which `popup.css` fades after 3 s, or "Not saved". `browser.run` runs a program synchronously up to its first asynchronous step (`syncStep`), and the popup may close at once, so `keep` calls `save` before anything asynchronous (starting a fiber, as `both` does, counts), timing the spinner with `IO.monotonic`. One `onInput` handler on the popup's root clears the problem, as each control's input event bubbles up to it, except the slider's, which clears it on `change`. The slider is named by `aria-labelledby` and read out by `aria-valuetext`, its `<output>` hidden from screen readers. All run their programs through `browser.run`, never `unsafeRunAndForget`.
- Laminar stays out of the pages' bundle too, within `popup()` and `Popup`: `grep -c com.raquo` on `omnibrowser-content.js` should find nothing. The content script edits the host page's text nodes directly, in plain DOM, through the library.
- `hosts` grants the background each provider's API (from Iris's `LlmProvider.origin`), so its requests do not depend on the API allowing CORS.
- Codecs are derived (`derives Codec`, circe's), except those of what is stored as a plain string: `Language` (its code, by Megalingual's codec), `LlmModel` (its `name`) and `Level` (its name). `Foreign` is kept by its name too. ### Gotchas

- A `/*` in a comment, as in a match pattern like `https://*/*`, opens a nested comment in Scala.
- On Windows, if `sbt` cannot start its server, run it with `sbt --server`.
- Run `omnibrowserPackage` in an sbt of its own, not after `testFull` or `omnibrowserBuild` in one invocation: so run, its release link of the content bundle once hung for 15 minutes (`OmnibrowserPlugin.linkContent` awaiting it, no CPU), where alone it takes 20 s. A hung sbt left behind holds the build's boot lock ("server is already booting"), so no other sbt starts there until it is stopped.
- On Windows, a script that rewrites a source file in text mode (as Python's `open(p, 'w')`) writes CRLF. Scalafmt mends the code but not multi-line string literals, such as the model's instructions, which then hold `\r`; write with `newline=''`, and check with `git diff`'s CRLF warning.
- On Windows, if compiling fails with "A required privilege is not held by the client" while backing up a `.sjsir`, delete `target/out/sjs1/**/classes` (sbt 2's disk cache links them) and compile again.
- Git here pushes a branch to its upstream (`push.default=tracking`), and the token may bypass the ruleset that guards `main`. A branch made from `origin/main` tracks `main`, so `git push origin <branch>` lands on `main` without a PR. Make branches with `--no-track`, and push with an explicit target: `git push -u origin HEAD:refs/heads/<branch>`.

## Instructions

### Compilation and Diagnostics

- When the user asks for help with a compilation or type error, start by running `sbt compile` to see the error for yourself.
  If there are many errors, making it unclear which one the user is referring to, ask them to clarify, and then focus only on that issue.
- IntelliJ MCP integration is active. When a request seems to implicitly refer to something the user is looking at, always check
  `mcp__ide__getDiagnostics` first to see which file(s) are open and get associated diagnostics (errors, warnings, and info hints with line numbers).

#### Testing

- After making code changes, always run `sbt compile` to verify that issues are fixed and no new ones are introduced.
- Repeatedly retry upon failure until the build succeeds. If you are unsure how to fix an issue, ask for help or refer to existing code for examples.
- Before trying to fix an error, make sure you first understand it fully.
- You should never report that a feature is complete without testing it first.

### Code Style

- You must read the [Code Style Guidelines](docs/STYLE_GUIDE.md).

### Pull Requests

When asked to publish the code changes, your task is to open one or more pull requests (PRs) to merge the changes into `main` on GitHub:

- Use `git` to check what has changed as compared to the `main` branch on `origin`.
- If the changes are thematically linked, they can be published as a single PR.
- Otherwise, you'll need to divide the changes into multiple PRs using your own judgement.
- Each PR should have a singular focus, shouldn't break anything, and should be able to be merged independently.
- Ensure that all code is staged, committed and pushed. Ensure no new files are left uncommitted, and no debug code is left in the codebase.
- When creating a PR, ensure that the title and description are clear, informative, and comprehensive.
- All feature/bugfix/etc branch names should be formatted as "feature_<short description>" or "fix_<short description>" or similar.
- All PR titles should be formatted as "[<scope>] <Short summary>", e.g. "[renderer] Fixed colour inversion bug."
- Use the `gh` CLI to do the above.
